## 2. Phase 1 7R 전략 분류

> 일정 계수: Retire 0 / Retain 0 / Rehost·Relocate 1 / Replatform 2~3 / Refactor 5~10 (팀장 지정 계수).
> 규칙: Retire·Retain 을 전 항목에서 후보로 검토하고 기각 시 근거 명기. flag OFF·내장 단계는 Refactor 로 몰지 않는다.

| # | 대상 | Retire 검토 | Retain 검토 | 확정 R | 계수 | 근거·조건 |
|---|---|---|---|---|---|---|
| 1 | 영수증 인식 | 기각 — 실사용 유저 경로 | 기각 — Phase 1 대표 AI 경로·서버리스 실증 목적 그 자체 | **Refactor** | 5~10 | HTTP 202+인프로세스 async → 이벤트 흐름 재구성 필요(계획의 S3 트리거 전제는 D-11 로 무효 — 원본 미저장). 실행환경은 팀 결정 대기: Lambda(+NAT 고정비, PF-04) vs **Cloud Run 서울**(11_실측 §5 NEW-02 — 레지던시·NAT 소멸). 같은 Refactor 라도 산출물이 전혀 다름 |
| 2 | 영상→레시피 | 기각 — 실사용·발표 방어 논거(pegasus 대조) | 후보였음 — 기각: #1 과 동일 Vertex 스택이라 한 번에 움직이는 편이 싸다 | **Refactor** | 5~10 | 120s 상한 < Lambda 15분. Redis 30일 캐시·단일비행 락 대체 설계 필요. 실행환경 결정은 #1 과 동일 결정에 묶임 |
| 3 | 챗봇 | 기각 — 실사용 기능(가드·멀티턴 실가동) | **채택 — Retain** | **Retain** | 0 | 라이브 = template, **LLM 호출 0**(D-07) — 이전해도 '서버리스 AI' 실증 기여 없음, 456ms 비교 논거도 과녁 상실. LLM refine 활성화는 팀 결정 — 결정 후 재분류. PF-13(API GW 진입점) 심각도도 이에 따라 하락 |
| 4 | 리뷰 요약 | 기각 — 실서비스 산출물(요약 노출) | 기각 — 배치 치환은 저위험·고실증 | **Replatform** | 2~3 | CronJob→EventBridge Scheduler+Lambda, 코드(증분·멱등) 재사용. **8/8 에 B(Distributed Map) 선택 시 Refactor 5~10 으로 승격** — PF-05 판정: 토 인계·월 착수 일정이면 A(그대로 이식) 유력 |
| 5 | 냉장고 추천 | **부의 — 서빙 Deployment 정지(사실상 Retire)를 팀 결정에 올림**(호출 0 인데 상시 가동·PVC 점유) | **채택 — Retain(이전 제외)** | **Retain** | 0 | `RANKING_ML_ENABLED=false`·호출 0(D-18) — 호출 없는 워크로드를 Refactor 로 몰지 않는다(지시 준수). PoC A절 LightGBM 측정도 함께 소멸 |
| 6 | 가격 이상탐지·핫딜 | 기각 — 실가동 알림 경로 | 기각 *(1단계 정정 — 탐지 배치는 이전, 체인은 잔존)* | **Replatform (탐지 배치 한정)** | 2~3 | 무상태 z-score 배치 → Scheduler+Lambda. **경계 = Kafka 발행까지** — 컨슈머+KEDA+DLQ+PG 상태는 온프렘 잔존이라 경로 절단 없음. 선행 조건 = 온프렘 Kafka·PG 인바운드 경로(D-3 검증 축) — 충족 전 착수 금지 |
| 7 | 재료명 NER 백필 | 기각 — 백필 산출물은 실사용(gazetteer 보강) | 기각 *(1단계 정정 — 저빈도 배치 = 서버리스 적합)* | **Replatform (배치 한정)** | 2~3 | 저빈도 배치는 서버리스 최적(미호출 시 비용 0) — "배치 전용"은 부적합이 아니라 적합 사유. 선행 조건 = **CRF 모델 아티팩트 확보**(이미지·git 에 없음·백업 소재 [미확인] F-14) — 확보가 이전의 첫 작업이자 백업 리스크 해소를 겸한다 |
| 8 | 리뷰 감정 분류 | 기각 — 실서비스 14만 건 경로(11_실측 §3 🔴) | 기각 — #4 와 동형·저위험 | **Replatform** | 2~3 | CronJob→Scheduler+Lambda, ON CONFLICT 멱등 재사용. 대량 백필 국면만 PF-05 결론(ID-only payload·인라인 불가) 적용. 8/13 스로틀 테스트는 PF-06 결론대로 배치 시간대 밖 |
| 9·10 | 품목 분류·구조화 추출 | — | — | (없음) | 0 | 독립 워크로드 아님(#1·#2 에 내장) — R 배정 자체가 이중 계상. 소비기한 수동 스크립트만 Retain 0 |

### 집계와 권고

- **일정 계수 합계 (1단계 정정): 18~32** (Refactor 2건 10~20 + Replatform 4건 8~12). **권고 순서: #4·#8(확실한 승리) → #7·#6(선행 조건 — 아티팩트 확보·Kafka 경로 — 충족 시) → #1·#2(Refactor)는 실행환경 팀 결정(Lambda vs Cloud Run) 직후 착수, 결정 전 IaC 착수 금지**(같은 R 이라도 산출물이 다름 — 11_실측 §5 7R 영향 절). #6·#7 은 LLM 미사용이라 레지던시 결정(D-1)과 무관하게 착수 가능.
- 계획 대비 범위 재편 (1단계 정정): AI 10종 → **실이전 6종(전면 4 + 배치 한정 2) + Retain 1종(#3) + 제외 1종(#5) + 내장 2종**. 8/7 PoC A절(CRF·LightGBM 저지연)은 대상 소멸로 재정의 필수 — PF-01 의 A-3′ 교체안은 PoC 재정의 후에만 의미 있음.
- 미결(팀 결정 대기, 단독 확정 금지): ① 레지던시 원칙 A/B/C(11_실측 §6) = #1·#2 실행환경 ② 챗봇 LLM 활성화 여부 = #3 재분류 ③ 랭킹 서빙 정지(Retire) ④ 8/8 요약 배치 A/B.
