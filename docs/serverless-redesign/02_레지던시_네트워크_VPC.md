## 축① 데이터 레지던시 · 네트워크 경로

### 1-0. 확정 전제 (재조사 금지)

- 채택 모델 2종(`amazon.nova-micro-v1:0` · `anthropic.claude-3-5-sonnet-20241022-v2:0`)은 서울 ON_DEMAND 불가 — **APAC 프로파일 필수, 요청이 도쿄·서울·싱가포르·시드니·뭄바이 5리전으로 라우팅** [출처: 11_실측발견 §1·§1-1, CLI 원문 FACTS/bedrock-*.json, 조회 2026-08-07].
- VPC 엔드포인트(PrivateLink)를 써도 **리전 간 라우팅은 그대로** — 레지던시 문제를 해결하지 못한다 [출처: 11_실측발견 §2].
- Vertex Gemini 는 서울(asia-northeast3) 네이티브 호출이 실물 가동 중 [출처: FACTS/02_as_built D-02, `GCP_LOCATION` env].
- 이전 대상 중 Bedrock 의존 = #4(sonnet v2)·#8(nova-micro), Gemini 의존 = #1·#2. 챗봇은 Retain·LLM 호출 0 이라 이 축의 대상이 아니다 [출처: 01_이전대상_7R §1·§2].

### 1-3. 온프렘 경로 후보 (Lambda/Cloud Run → 온프렘 PG — 경로 수준만, 배선은 다음 창)

이전 대상 4종 전부 결과를 온프렘 PG 에 쓴다(#1·#2 결과 저장, #4·#8 UPDATE — Phase 1 에서 DB 는 온프렘 잔존). 어느 안을 골라도 이 경로는 필요하다.

| 후보 | 실물 상태 | 성격 | 평가 |
|---|---|---|---|
| Site-to-Site VPN | 없음 — 즉시 신청 목록 #7(조건부) | 인바운드 IPsec, 리드타임 최장 [미확인] | 표준적이나 8/18 창에서 리드타임이 임계경로 [출처: 06_열린질문 §1 #7] |
| **Cloudflare Tunnel 계열** | **이미 가동 중** — mp-ingress ns, `app.mealbong.cloud`→게이트웨이 `.14` [출처: 11_실측발견 §4 NEW-01, FACTS/02 NEW-01] | 아웃바운드 터널(온프렘→CF). 현 용도는 공개 HTTP 유입 — **PG TCP 를 태우려면 별도 터널/Access 구성 필요** [미확인 — TCP 터널 구성 가능 여부·지연은 검증 항목] | 리드타임 0(계정·데몬 실물 존재)이 최대 강점 — H축 비교에 필수 포함 [출처: 06_열린질문 §1-1] |

### 2-3. "상시 NAT" 자체를 의심한다 — 대안 검토

이전 대상 4종의 실가동 프로필: #4 = 주 2회 08:00 배치, #8 = 매일 07:00 배치(각 회당 소요 [미확인 — 수십 분 추정]), #1·#2 = 온디맨드 API [출처: FACTS/02 §2]. **배치 2종의 월 실가동은 많아야 수십 시간인데 NAT 는 730시간 전부 과금된다** — 가동률 기준 수십 배의 유휴 과금 구조다 [추정: 월 실가동 ≤30h 가정 시 730/30 ≈ 24배].
