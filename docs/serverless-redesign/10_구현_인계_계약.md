# 10_구현_인계_계약.md — 함수 단위 구현 계약표 (2026-08-07)

> 읽는 사람: 월요일(8/10) 구현 착수 세션. **이 문서만으로 첫 커밋이 가능해야 한다.**
> 범위 = 이전 대상 6종(영수증 인식 · 영상→레시피 · 리뷰 요약 · 감정 분류 · NER 백필 배치 · 가격 탐지 배치). **챗봇·냉장고 추천은 구현 대상이 아니다 — 표에 없다.**
> 결정 종속: **D-1(레지던시 A/C)·D-3(VPC 배치)·D-6(EKS 선후)은 결정 대기 중** — 종속 셀은 "A안일 때 / C안일 때"로 병기. D-6 답이 '가'(EKS 선행)이면 네트워크 관련 셀 전체 재검토.
> 수치 표기: 값 또는 "미결정 + 결정 주체 + 시한". 타임아웃·메모리·동시성의 초기값은 전부 [추정 — 8/13 측정 후 조정].

## 1. 함수 분할 입도

**워크로드 6종 → 함수 8개.** 근거 3줄:

1. **워크로드당 1함수가 기본** — IAM 역할·알람·롤백 단위가 서비스 경계와 일치해 병행 운영 중 원인 분리가 된다.
2. **동기 2종(영수증·영상)만 접수/처리 2함수로 분리** — Lambda 는 응답 반환 후 백그라운드 실행이 보장되지 않아 현행 인프로세스 asyncio 구조를 그대로 이식할 수 없고, 접수↔처리 사이를 SQS 로 이으면 재시도·DLQ 가 명시 제어된다.
3. **그 이상 쪼개지 않는다(8개 고정)** — 폴링 분리·처리 단계 분할은 계약 수와 콜드스타트 표면만 늘린다. 함수 추가는 이 문서 개정을 통해서만.

## 5. 첫 PR 범위와 착수 순서 (8/10 월요일)

> ⚠️ **IaC 에 VPC/NAT "부재"를 하드코딩하지 마라.** D-3·D-6 확정 전에는 VPC 있음도 없음도 확정이 아니다 — SAM 템플릿의 VPC 설정은 파라미터로 비워 두고, 기본값 없이 명시 주입만 허용한다.

DB 경로 의존도 확인: 6종 전부 PG RW 가 필요해 **의존 유무로는 차이가 없다.** 차이는 **민감도**다 — 배치 4종은 비동기·멱등·재실행 안전이라 경로 지연·불안정에 관대하고, 동기 2종은 유저 대기 경로다. **따라서 배치부터 착수한다.**

## 6. 하지 말아야 할 것 (다음 세션이 저지르기 쉬운 실수)

1. **챗봇·냉장고 추천을 구현 대상으로 오인** — 계약표에 없다. 챗봇은 Retain(LLM 호출 0), 랭킹은 제외(flag OFF).
2. **S3 이벤트 트리거 배선** — 영수증 원본은 어디에도 저장되지 않는다(실사 확정). 계획 문서의 그 전제는 무효다.
3. **Bedrock IAM 을 모델 ARN 단독 한정으로 작성** — 그대로 AccessDenied. 프로파일 ARN + 5리전 모델 ARN 동시 허용(계약표 §2).
4. **D-3·D-6 결정 전에 VPC 구성을 확정 커밋** — "VPC 없음"을 확정으로 굳히는 것도 위반이다(§5 주의).
5. **Kafka 컨슈머·KEDA·DLQ 체인까지 이전 시도** — 가격 탐지의 경계는 "발행까지"다. 컨슈머는 온프렘 잔존.
6. **인프라 계층 설계에 손대기** — EKS·DB 토폴로지·네트워크·관리형 DB 전환은 팀장 소관. AI 파트 산출물에 그 결정을 전제로 쓰지 마라.
7. **`fb-` 접두사로 신규 이름 생성** — 전부 `mp-`(CLAUDE.md). 기존 `fb-` 실물은 참조만.
8. **`services/`·`pipelines/` 원본 수정** — 동결. 함수 코드는 `serverless/` 에서만.
9. **$LATEST·`:latest` 운용** — 버전 발행 + `live` 별칭 이동만. 이미지/아티팩트 핀은 불변 식별자로.
10. **Lambda 에 정적 AWS 키를 env 로 주입** — 실행 역할만 쓴다. 키 제거 4단계(축⑤ 5-3)의 목적 자체를 무너뜨리는 행동.
11. **온프렘 CronJob suspend/삭제를 함수 배포와 동시에 수행** — 병행 운영이 기본, 컷오버는 별도 결정(비가역 대장 #5·#6).
12. **계약표 밖 함수 추가** — 8개 고정. 늘리려면 10_구현_인계_계약.md 개정이 먼저다.
