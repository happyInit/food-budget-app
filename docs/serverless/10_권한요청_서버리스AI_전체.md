함수는 **총 10개**이고 지금 이렇습니다.

| | 함수 | 상태 |

| 🟢 배포됨 | `video-api` · `ocr-api` · `video-worker` | 실동작 확인 |

### 2. 🔴 요청 ① — ALB 배선 (핵심, 이거 하나가 실질 블로커입니다)

**무엇** — ALB `mp-alb-public` 의 443 리스너에 규칙 3개 + Lambda 타깃그룹 3개.

**왜** — 위 3개 함수는 HTTP 로 받는 함수입니다. 지금은 존재하지만 **아무 요청도 닿지 않아서**
`aws lambda invoke` 로만 확인할 수 있습니다. 프론트에서 쓰려면 리스너 규칙이 필요합니다.

**🔵 경로를 빼앗지 않습니다** — 기존 파드 경로는 그대로 두고 `/ai` 접두사를 씌웠습니다:

```
/ai/api/recipes/extract*        → mp-ai-video-api
/ai/api/pantry/ocr*             → mp-ai-ocr-api
/ai/api/mealplan/assistant/chat → mp-ai-chat-api
```

`/api/pantry/ocr` 는 **계속 파드로 갑니다.** 컷오버가 아니라 병렬입니다.
(컷오버를 하기로 정하시면 접두사 변수 한 글자만 지우면 됩니다 — 그건 그때 따로 여쭙겠습니다.)

**🔴 지금 왜 안 되나** — 두 군데서 막힙니다.

1. `mp-ai-guardrails` 의 `DenyTouchingMigrationInfra` 가 `elasticloadbalancing:Create*`·`Delete*` 를 `Resource: "*"` 로 **명시 Deny**
2. `mp-ai-boundary` 의 `CeilingHardDeny` 가 `elasticloadbalancing:*` 를 Deny

명시 Deny 라 Allow 를 아무리 붙여도 이깁니다. **둘 다 손대야 합니다.**

**드리는 제안** — *«LB 는 인프라 소관»* 이라는 C-77 을 깨지 않는 선에서 두 가지 중 편하신 쪽으로:

> **(A) 저에게 좁은 권한을 주시는 방법** — 제가 스스로 진행하고, 끝나면 회수하셔도 됩니다.
> **(B) 인프라에서 직접 붙이시는 방법** — 제 `alb.tf` 를 그대로 드리겠습니다. 값은 다 채워져 있습니다.

**(A) 를 고르실 경우 필요한 변경 — 이 세 조각입니다.**

`mp-ai-dev` 에 추가:

```json
{
  "Sid": "AlbTargetGroupsMpAiOnly",
  "Effect": "Allow",
  "Action": [
    "elasticloadbalancing:CreateTargetGroup",
    "elasticloadbalancing:DeleteTargetGroup",
    "elasticloadbalancing:ModifyTargetGroupAttributes",
    "elasticloadbalancing:DescribeTargetGroupAttributes",
    "elasticloadbalancing:RegisterTargets",
    "elasticloadbalancing:DeregisterTargets",
    "elasticloadbalancing:AddTags",
    "elasticloadbalancing:RemoveTags"
  ],
  "Resource": "arn:aws:elasticloadbalancing:ap-northeast-2:689192361171:targetgroup/mp-ai-*/*"
},
{
  "Sid": "AlbRulesOnPublicHttpsListenerOnly",
  "Effect": "Allow",
  "Action": [
    "elasticloadbalancing:CreateRule",
    "elasticloadbalancing:ModifyRule",
    "elasticloadbalancing:DeleteRule",
    "elasticloadbalancing:SetRulePriorities",
    "elasticloadbalancing:DescribeRules"
  ],
  "Resource": [
    "arn:aws:elasticloadbalancing:ap-northeast-2:689192361171:listener/app/mp-alb-public/764f4168e39fe43d/09093fd4be4dba67",
    "arn:aws:elasticloadbalancing:ap-northeast-2:689192361171:listener-rule/app/mp-alb-public/764f4168e39fe43d/09093fd4be4dba67/*"
  ]
}
```

`mp-ai-guardrails` 의 `DenyTouchingMigrationInfra` — **`elasticloadbalancing:Create*` / `Delete*` 글롭을 지우고, 구조를 바꾸는 액션만 이름으로 남기는 형태**를 제안드립니다:

```json
"elasticloadbalancing:CreateLoadBalancer",
"elasticloadbalancing:DeleteLoadBalancer",
"elasticloadbalancing:ModifyLoadBalancerAttributes",
"elasticloadbalancing:SetSecurityGroups",
"elasticloadbalancing:SetSubnets",
"elasticloadbalancing:SetIpAddressType",
"elasticloadbalancing:CreateListener",
"elasticloadbalancing:DeleteListener",
"elasticloadbalancing:ModifyListener"
```

⇒ **LB·리스너 자체는 여전히 제가 못 건드립니다.** 규칙과 타깃그룹만 열립니다.
`mp-ai-boundary` 의 `CeilingHardDeny` 에서도 `elasticloadbalancing:*` 를 같은 목록으로 좁혀 주셔야 합니다.

**🔴 남는 위험을 숨기지 않고 말씀드립니다 — 그리고 이건 제가 생각했던 것보다 예민합니다.**

현재 443 리스너 규칙은 이렇습니다(조회 결과):

```
100      host = aws.mealbong.cloud   → forward        ← 경로를 안 따집니다
default                              → fixed-response
```

100번이 **그 호스트의 모든 경로**를 잡습니다. 그래서 제 규칙을 200번에 두면 **거기까지 안 내려옵니다** —
함수도 있고 규칙도 있는데 요청이 0건인 상태가 됩니다.
🔴 즉 **제 규칙은 100번보다 앞에 서야 동작합니다.** 처음엔 200번으로 짜 뒀었는데 이번에 잡아서 고쳤습니다.

앞에 서는 만큼 조건을 좁혔습니다:

- 우선순위 **10–12** (100번 앞)
- 조건이 **두 개** — 경로 `/ai/*` **그리고** 호스트 `aws.mealbong.cloud`
  ⇒ `/ai` 로 시작하지 않는 요청은 종전 그대로 100번으로 갑니다. **파드 경로는 안 건드립니다.**
- 되돌리기 = 규칙 삭제 (타깃그룹은 남아도 무해)
- `DescribeRules` 로 언제든 감사 가능 — 규칙이 3개보다 많으면 뭔가 잘못된 겁니다

🔵 그리고 이 규칙들은 **ALB 에 이미 붙은 WAF 를 그대로 탑니다**(C-60). 우회로가 아닙니다.

⚠️ 이 부분이 불편하시면 **(B) 직접 적용** 쪽이 낫습니다. 우선순위를 앞에 두는 걸
직접 보고 결정하시는 게 맞다고 생각합니다.

### 3. ⚪ 요청 ② — CloudWatch 알람을 Terraform 으로 되돌리기

**무엇** — `mp-ai-dev` 의 `OwnResourcesFullControl` 에서
`cloudwatch:PutMetricAlarm`·`DeleteAlarms` **두 줄을 `cloudwatch:*` 한 줄로** 바꿔 주세요.
(자원 범위는 이미 `arn:aws:cloudwatch:*:689192361171:alarm:mp-ai-*` 로 좁혀져 있어 **범위는 안 넓어집니다.**)

**왜** — 알람 7개를 Terraform 으로 짰다가 되돌렸습니다. 알람은 잘 만들어지는데,
그다음 `plan` 이 **매번 죽었습니다**:

```
Error: listing tags for CloudWatch Metric Alarm (...): AccessDenied
```

프로바이더가 refresh 때 태그를 읽는데 `cloudwatch:ListTagsForResource` 가 없습니다.
🔴 **자원 하나가 스택 전체를 못 쓰게 만듭니다** — 그 상태로는 함수 배포도 못 합니다.
그래서 알람만 스크립트(`serverless/alarms.sh`)로 뺐는데, 이건 «코드로 관리되지 않는 것» 이 하나 느는 것이라
가능하면 되돌리고 싶습니다.

**급하지 않습니다.** 지금도 알람은 돌고 있습니다.

### 4. ⚪ 요청 ③ — 보안그룹 **규칙** 태깅

**무엇** — `mp-ai-dev` 의 `TagOnCreateOnly` 자원에
`arn:aws:ec2:*:689192361171:security-group-rule/*` 를 추가하고,
조건 `ec2:CreateAction` 에 `AuthorizeSecurityGroupIngress`·`AuthorizeSecurityGroupEgress` 를 더해 주세요.

**왜** — 지금은 `security-group/*` 에만 걸려 있어서 **규칙에 태그가 안 붙습니다.**
그래서 Lambda SG 의 이그레스 규칙을 Terraform 이 관리하지 못하고 **손으로 만든 채 방치**돼 있습니다.
(누가 지워도 `plan` 에 안 잡힙니다 — 아래 5번과 같은 사고가 여기서도 가능합니다.)

### 5. ⚪ 요청 ④ — `ec2:DescribeNetworkInterfaces` (읽기 전용)

VPC Lambda 는 ENI 를 만들어서 붙습니다. 그게 실패하면 함수가 `INIT` 에서 죽는데,
지금 저는 **ENI 를 볼 수 없어서**(`implicitDeny`) 원인이 «서브넷인지 · SG 인지 · IP 고갈인지» 를 못 가립니다.
읽기 전용 한 줄입니다.

| | 요청 | 급함 | 없으면 |
|---|---|---|---|
| ① | ALB 배선 (권한 or 직접 적용) | 🔴 **높음** | 함수 3종에 요청이 안 닿음 |

## 부록 — 실측 근거 (메시지에 안 넣음)

### 왜 «명시 Deny 두 곳» 인가

```
elasticloadbalancing:CreateTargetGroup    explicitDeny
elasticloadbalancing:CreateRule           explicitDeny
elasticloadbalancing:ModifyRule           explicitDeny
```

`simulate-principal-policy` 결과다. 🔴 단 **이 도구는 자원 ARN 없이 부르면 틀린 답을 준다** —
같은 날 `lambda:AddPermission`·`sns:Subscribe`·`cloudwatch:PutMetricAlarm` 이 `*` 기준으로는
`implicitDeny` 로 나왔지만 **실제 ARN 을 주면 전부 `allowed`** 였다.
그래서 위 세 건도 ARN 을 주고 다시 확인했고, 결과가 같았다.

### 배포된 정책 = 레포와 동일 (v3)

`mp-ai-dev` · `mp-ai-guardrails` · `mp-ai-boundary` 전부 v3 이고 레포 JSON 과 Sid 단위로 차이가 없다.
⇒ **«이미 합의했는데 안 붙은 것» 은 하나도 없다.** 위 요청은 전부 신규다.

### 이미 있어서 요청하지 않는 것

- `lambda:*`·`ecr:*`·`s3:*`·`sqs:*`·`scheduler:*`·`logs:*`·`secretsmanager:*`·`states:*` on `mp-ai-*`
- `bedrock:InvokeModel` (모델 목록 조회 확인 — Claude 계열 접근 열려 있음)
- `iam:CreateRole` + 경계 강제 + `PassRole` (서버리스 서비스 한정)
- `ec2:CreateSecurityGroup`·`Authorize*` (자기 SG 한정)
- `lambda:CreateEventSourceMapping` (8/17 에 `lambda:FunctionArn` 조건부로 자체 해결)
- `sns:*` on `mp-ai-*` — 알람 토픽·구독 등록 가능

### C-85 의 대가 — 기록해 둔다

`pg_host` 가 **노드 사설 IP 한 개**다(LB 0개). 그 노드가 교체되면 주소가 죽는다.
MNG 고정 노드라 교체는 업그레이드 때뿐이지만, 그 순간을 잡는 것은 `serverless/alarms.sh` 의
① 함수 오류 알람 하나뿐이다. 🔵 되돌리는 길은 C-85 가 명시한 대로 NLB 승격이고,
그때 `pg_port`·`es_port` 에 5432·9200 을 넣으면 코드는 그대로 산다(MR !84).
