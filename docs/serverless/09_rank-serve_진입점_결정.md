# `rank-serve` 진입점 결정 — 🔵 **Lambda 로 옮기지 않는다. 파드로 남긴다.**

**작성 2026-08-17 · AI 파트**
11종 중 이 하나만 «부르는 쪽이 브라우저가 아니라 파드» 라 진입점이 미결이었다. 그걸 닫는다.

---

## 0. 결론

> **`mp-ai-rank-serve` 를 배포하지 않는다.** 랭킹 서빙은 EKS 파드(`mp-ranking-serving`)로 둔다.
> 코드(`serverless/ai_rank_serve/`)와 Dockerfile 은 **지운다.** 남겨 두면 «언젠가 쓸 것» 으로
> 보여서 그때마다 이 판단을 다시 하게 된다.

---

## 1. 무엇이 걸려 있었나

`mealplan` 파드가 `RANKING_SERVING_URL` → `POST /rank/personalize` 로 부른다. 브라우저가
아니므로 공개 ALB 에 붙이면 안 되고, 후보가 둘이었다:

| 안 | 비용 | 코드 변경 | 우리가 만들 수 있나 |
|---|---|---|---|
| 내부 ALB | ≈ $16/월 | 0 (환경변수만) | 🔴 **못 만든다** — `elasticloadbalancing:Create*` explicitDeny |
| Function URL + SigV4 | $0 | `mealplan` 에 boto3 + 서명 | 🟢 `lambda:CreateFunctionUrlConfig` allowed |
| **파드 유지** | $0 | **0** | 🟢 아무것도 안 함 |

---

## 2. 🔴 그런데 진입점보다 먼저 물었어야 할 것이 있다 — **Lambda 가 맞는 자리인가**

### 2.1 콜드스타트가 그대로 사용자 체감이 된다

`serve.py` 는 **import 시점에** 모델을 언피클한다(`_init_from_env`). 로컬에서 재 봤다:

```
import + 모델 로드   1.08s · 1.04s · 1.07s      (x86 · sklearn 만 · 따뜻한 파일시스템)
비교: chat 진입점    0.64s
```

🔴 **이건 하한이다.** 실제는 더 크다 — ① arm64 Graviton 이고 ② lightgbm 이 더해지며
③ 컨테이너 이미지라 첫 pull 이 있고 ④ VPC ENI 부착이 얹힌다.

그리고 이 경로는 **추천 요청마다** 탄다. 동기·지연민감 경로에 초 단위 콜드스타트를 놓는 것은
«서버리스라서 좋다» 가 아니라 **그냥 느려지는 것**이다.

### 2.2 서버리스가 주는 이득이 여기서는 거의 없다

| 서버리스의 이득 | 이 함수에서는 |
|---|---|
| scale-to-zero | 🔴 추천은 상시 호출된다 — 0 으로 안 내려간다 |
| 요청당 과금 | 🔴 상시 호출이면 파드가 더 싸다 |
| 운영 부담 감소 | 🔴 오히려 **는다** — 11종 중 **유일하게 컨테이너**라 별도 ECR·빌드 경로가 생긴다 |
| 빠른 배포 | ⚪ 파드도 ArgoCD 로 같다 |

### 2.3 그리고 이미 잘 돌고 있다

`mp-ranking-serving` 파드는 살아 있고 모델이 적재돼 있다(`model_loaded: true` · `/app/ranker.pkl`
702,418 B · C-20 대로 이미지에 구움). **고칠 것이 없는 것을 옮기는 셈**이다.

---

## 3. 그래서 «진입점을 무엇으로 하나» 가 아니라 «옮기지 않는다» 가 답이다

세 후보 중 둘(내부 ALB · Function URL)은 **비용이나 코드를 더하면서 위 2.1~2.2 를 하나도
해결하지 못한다.** 남는 것은 파드 유지이고, 그건 **작업이 0** 이다.

🔵 이 판단은 «서버리스를 안 한다» 가 아니다 — 나머지 10종은 그대로 간다.
   그것들은 **배치**(수시로 안 돎)이거나 **접수·워커**(비동기라 콜드스타트가 유저에게 안 보임)
   이거나 **챗**(호출이 드물고 콜드스타트를 감내할 수 있음)이다. 랭킹만 성질이 다르다.

## 4. 되돌릴 조건

아래가 바뀌면 다시 본다:
- 추천 호출이 **드물어져** scale-to-zero 가 의미를 갖게 될 때
- 모델이 **가벼워져** 콜드스타트가 수백 ms 대로 내려갈 때(예: lightgbm 을 버리고 순수 numpy 추론)
- Lambda SnapStart 가 **파이썬·컨테이너**를 지원하게 될 때(현재 미지원)

## 5. 이 결정으로 없어지는 일

- `rank-serve` 진입점 결정 (미결 해소)
- `rank-serve` 전용 ECR 리포지토리·이미지 빌드 CI 잡
- `libgomp` 을 위한 컨테이너 경로 — 🔵 **`serverless/build.sh` 의 zip 규율이 11종 전부에 통일된다**
- 내부 ALB $16/월 (또는 `mealplan` 의 SigV4 코드)

⚠️ **남는 것 하나** — 재학습 이미지는 여전히 `libgomp` 이 필요하다. 다만 그건
`ml/recipe-ranking/Dockerfile` 이 이미 만들고 있고, 재학습은 EKS CronJob 이다
(`docs/serverless/08 §③`). **서빙과 학습이 같은 이미지를 쓰는 형상이 그대로 유지된다.**
