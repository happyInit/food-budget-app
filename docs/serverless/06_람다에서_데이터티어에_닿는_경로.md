# Lambda 가 PG·ES 에 닿는 경로 — 🔴 «NodePort» 전제는 틀렸다

**작성 2026-08-17 · AI 파트 · 실측 기반**
대상 = `docs/mp_aws_prep_checklist.md` 의 선행 작업 중 *"NodePort + 노드 사설 IP"* 로 적혀 있던 항목.

> 이 문서는 **인프라 담당에게 넘기는 요청 명세**다. 실행은 인프라 소관이고, 여기서는
> ① 왜 종전 안이 안 되는지 ② 무엇이 맞는지 ③ 얼마나 드는지를 **실측으로** 적는다.

---

## 0. 한 줄

**NodePort 가 아니라 «내부 NLB(IP 타겟)» 이다.** 이 클러스터는 Karpenter 로 노드가 수시로
갈리고(오늘 실측), Cilium 이 ENI 모드라 파드가 **진짜 VPC IP** 를 받으며, 그 형상을 쓰는
타겟그룹이 **이미 돌고 있다.** 종전 안은 «노드가 고정» 이라는 전제 위에 서 있었는데 그 전제가 없다.

---

## 1. 왜 필요한가 — 지금 상태

Lambda 11종 중 **8종이 PG 를 친다**(배치 5 · `chat-api` · `rank-serve` · `ocr-worker`).
그런데 `data` 네임스페이스의 **Service 11개가 전부 ClusterIP** 다(2026-08-17 실측):

```
es-es-a  es-es-b  es-es-http  es-es-internal-http  es-es-transport
mp-elasticsearch-exporter  pg-pooler  pg-r  pg-ro  pg-rw  redis-pgsync
                                                    ↑ 전부 ClusterIP
```

ClusterIP 는 **클러스터 안에서만 유효한 가상 IP** 다. VPC 안의 Lambda 는 그 이름도 그 주소도
해석하지 못한다. ⇒ 이 배선이 없으면 **8종이 한 발도 못 나간다.**

🔵 **반대로 3종은 이 작업 없이도 된다** — `video-api` · `video-worker` · `ocr-api`.
셋 다 Valkey(ElastiCache · VPC 네이티브)와 SQS·S3 만 쓴다. ⇒ **권한만 오면 먼저 올릴 수 있다.**

---

## 2. 🔴 종전 안(NodePort)이 왜 안 되나 — 오늘 실측

### 2.1 노드가 고정이 아니다

```
NAME                  IP             생성              소속
ip-10-10-64-103…      10.10.64.103   08-13 07:58      mp-mng-general   ← 관리형 노드그룹
ip-10-10-82-223…      10.10.82.223   08-13 07:58      mp-mng-general
ip-10-10-84-79…       10.10.84.79    08-17 05:38      mp-burst         ← 🔴 Karpenter, 5분 전
ip-10-10-89-36…       10.10.89.36    08-17 05:39      mp-burst         ← 🔴 Karpenter, 5분 전
```

Karpenter(`nodepool/mp-burst`)가 부하테스트 중에 **노드 2대를 새로 띄웠다.** 부하가 빠지면
consolidation 으로 사라진다. 즉 **노드 IP 는 수명이 분 단위인 값**이다.

NodePort 로 가면 Lambda 환경변수에 노드 사설 IP 를 박아야 하는데:
- 🔴 노드가 갈릴 때마다 **함수 8개의 설정**을 고쳐야 한다. 자동화하면 그게 또 하나의 시스템이다.
- 🔴 관리형 노드그룹(고정 2대)만 대상으로 좁혀도 **AMI 갱신 = 노드 교체 = IP 변경**이다.
- ⚠️ 완화책은 있다 — psycopg 는 `host=a,b,c` 다중 호스트를 받는다. 그래도 «목록을 최신으로
  유지하는 사람» 이 필요하고, 그 사람이 잊으면 **장애가 조용하다**(연결이 하나씩 줄어든다).

### 2.2 그리고 굳이 그럴 이유가 없다 — 더 나은 길이 이미 깔려 있다

| 확인한 것 | 값 | 뜻 |
|---|---|---|
| Cilium `ipam` | **`eni`** | 파드가 **진짜 VPC IP** 를 받는다 |
| Cilium `routing-mode` | **`native`** | 오버레이가 아니다 — VPC 라우팅으로 직접 닿는다 |
| 파드 IP 실측 | `es-es-a-0` = `10.10.66.13` | VPC CIDR `10.10.0.0/16` **안**이다 |
| AWS Load Balancer Controller | `kube-system` 에 **설치됨**(2일 전) | 어노테이션만으로 NLB 생성 가능 |
| 기존 ALB 타겟그룹 | `mp-tg-gw-public` · **`target-type: ip`** | **이 형상이 이미 프로덕션에서 돈다** |

즉 «파드 IP 를 직접 타겟으로 잡는 로드밸런서» 는 **가설이 아니라 지금 도는 것**이다.
공개 진입점이 정확히 그 방식이다.

## 3. 요청 사항 — 내부 NLB 2대

### 3.1 만들 것

| # | 대상 | 셀렉터 | 포트 | 소비자 |
|---|---|---|---|---|
| ① | **PG (Pooler)** | `cnpg.io/poolerName=pg-pooler` | 5432 | Lambda **8종** |
| ② | **Elasticsearch** | `elasticsearch.k8s.elastic.co/cluster-name=es` | 9200 | `chat-api` **1종** |

🔴 **기존 Service 를 고치지 말고 «추가» 한다.** `pg-pooler`·`es-es-http` 는 각각 CNPG·ECK
**오퍼레이터가 소유**한다 — 직접 수정하면 오퍼레이터가 되돌리고, 그 싸움이 조용히 반복된다.
⇒ 같은 파드를 고르는 **새 Service** 를 옆에 세운다(C-83 «덧셈» 원칙과 같은 축).

```yaml
# 이름은 mp- 접두사 규칙을 따른다. 실체 배치는 인프라 판단.
apiVersion: v1
kind: Service
metadata:
  name: mp-pg-lambda            # ES 쪽은 mp-es-lambda
  namespace: data
  annotations:
    service.beta.kubernetes.io/aws-load-balancer-type: "external"
    service.beta.kubernetes.io/aws-load-balancer-nlb-target-type: "ip"      # ← §2.2 근거
    service.beta.kubernetes.io/aws-load-balancer-scheme: "internal"          # 🔴 인터넷 노출 금지
    service.beta.kubernetes.io/aws-load-balancer-subnets: "<node 서브넷 2AZ>"
spec:
  type: LoadBalancer
  selector: { cnpg.io/poolerName: pg-pooler }
  ports: [{ port: 5432, targetPort: 5432 }]
```

### 3.2 보안그룹

Lambda ENI SG **→** 대상 파드 SG, TCP 5432 / 9200 **인바운드 한 줄씩.**
🔴 `0.0.0.0/0` 이 아니라 **SG 참조**로 열 것 — NLB 가 internal 이어도 VPC 안의 아무나
붙는 것과 Lambda 만 붙는 것은 다르다.

### 3.3 Lambda 쪽 배치

**노드 서브넷**에 붙인다(`mp-subnet-node-*` × 2AZ). 데이터 서브넷은 «밖으로 나가는 경로 없음» 이
산출물이라(`vpc_service.tf`) 거기 두면 아래 §4 가 전부 막힌다.

## 4. 🔵 확인해 둔 것 — Lambda 를 VPC 에 넣어도 바깥이 막히지 않는다

VPC Lambda 는 기본적으로 인터넷이 안 나간다. 이 VPC 는 이미 갖춰져 있다:

| 필요한 것 | 어떻게 나가나 | 비용 영향 |
|---|---|---|
| **SQS** (video·ocr 잡 큐) | Interface EP `sqs` (C-56) | NAT 안 탐 |
| **Secrets Manager** (비밀) | Interface EP `secretsmanager` | NAT 안 탐 |
| **STS** (역할 교환) | Interface EP `sts` | NAT 안 탐 |
| **S3** (모델·영수증) | **Gateway EP**(무료) | NAT 안 탐 |
| **Bedrock** (chat refine · 리뷰 배치) | 🔴 **EP 없음 → NAT** | NAT 데이터 요금 발생 |
| **Gemini** (video·ocr 추출) | 🔴 외부 인터넷 → NAT | 위와 같음 |

⇒ **막히는 것은 없다.** 다만 Bedrock·Gemini 트래픽이 NAT 1대(C-47)를 지난다.
⚠️ 그래서 **NAT 가 AZ-a 와 함께 죽으면 AI 생성 경로가 같이 죽는다** — 새로 생기는 사실이 아니라
지금 파드에서도 같고, C-56 이 «보험» 을 SQS·SM·STS 에만 든 이유이기도 하다. 기록만 해 둔다.

## 5. 비용

내부 NLB ≈ **시간당 $0.0225 + LCU** ⇒ 1대 월 **약 $16**.

| 안 | 월 비용 | 푸는 것 |
|---|---|---|
| **A. PG + ES 둘 다** | 약 **$33** | **11종 전부** |
| **B. PG 만 먼저** | 약 **$16** | **10종**(`chat-api` 만 남음) |
| C. NodePort | $0 | 8종 — 단 §2 의 유지보수 부채를 계속 진다 |

### 🔵 권고 = **B → A**

**PG NLB 1대를 먼저** 세우면 그것만으로 **10/11** 이 풀린다(`chat-api` 만 ES 를 쓴다).
$16 로 배치 5종 + `rank-serve` + `ocr-worker` + 이미 되는 3종이 전부 살아난다.
`chat-api` 는 ES NLB 를 더할 때 같이 켠다 — **학생 예산 제약**(CLAUDE.md) 아래에서
«쓰는 만큼만 먼저» 가 맞다고 본다.

🔴 C(NodePort)를 권하지 않는 이유는 비용이 아니라 **부채**다. $0 처럼 보이지만 노드가 갈릴
때마다 사람이 개입해야 하고, 잊으면 **연결이 하나씩 조용히 줄어든다.** 우리가 오늘 하루 동안
쫓은 결함들이 전부 그 «조용한» 부류였다.

## 6. 이 작업이 끝나면 무엇이 달라지나

Lambda 쪽에서 바뀌는 것은 **환경변수 두 개뿐**이다 — 코드는 한 줄도 안 바뀐다.

```
PGHOST = mp-pg-lambda-xxxx.elb.ap-northeast-2.amazonaws.com     # NLB DNS (안정적)
ESHOST = mp-es-lambda-xxxx.elb.ap-northeast-2.amazonaws.com
```

🔵 그렇게 설계해 뒀다(`serverless/README.md` §원칙 — 모르는 값은 코드에 박지 않는다).

## 7. 참고 — 이 문서가 근거한 실측 명령

전부 읽기 전용이고 부하테스트 중에 돌렸다.

```bash
kubectl -n data get svc                                  # 11개 전부 ClusterIP
kubectl get nodes -o custom-columns=…karpenter.sh/nodepool  # mp-burst 2대, 생성 5분 전
kubectl -n kube-system get cm cilium-config -o jsonpath='{.data.ipam}{.data.routing-mode}'
kubectl -n data get pods -o custom-columns=IP:.status.podIP  # 10.10.x = VPC CIDR
kubectl get deploy -A | grep aws-load-balancer-controller
aws elbv2 describe-target-groups --query 'TargetGroups[].TargetType'   # ip
```

⚠️ NAT·VPC 엔드포인트는 **AWS API 권한이 없어**(`ec2:DescribeNatGateways` 등) 콘솔로 못 봤고,
`infra/terraform/aws-platform/{endpoints.tf,vpc_service.tf}` 의 선언으로 확인했다.
선언과 실물이 어긋나 있다면 §4 의 표가 틀린다 — 인프라 담당이 한 번 봐 주면 좋겠다.
