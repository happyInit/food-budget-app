## 운영·구현된 기능 (결정 + 한계 + 해결)

### 1. RAG 챗봇 "밥풀이" — 🟢 운영
**결정:** 5단계 파이프라인(①질문분석 ②병렬검색 ③컨텍스트조립 ④생성 ⑤응답조립). Gemini refine은 **레시피 추천만** 다듬음(가격·영양은 template = 0원·환각0). 멀티턴(Redis), 가드레일 4층, 제외재료 마이페이지 영속, 냉장고 재고 읽기, recipe-in-focus 대화일관성.
**구성요소:** 의도분류(`extract._classify_intent`, 규칙 nutrition/recipe_cost/recommend/price + ML 보강 opt-in)는 ①단계 라우터 — template(④생성)과 별개.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| 냉장고 재고를 못 읽음(StubPantry) | **chat→pantry API 위임**(재료 미지정 추천 시 재고 item_id 주입) | ✅ 배포 |
| 후속발화가 직전 답 반복 | **반복 가드**(동일답 억제) + **recipe-in-focus**(선택 요리 상세응답) + 확인발화 소셜응답 | ✅ 배포 |
| 영양소 질의가 가격으로 오분류 | nutrition 키워드 보강(나트륨·지방·탄수화물 등) | ✅ 배포 |
| "그거 재료/몇분/칼로리" 드릴다운 이탈 | 초점(focus) 활성 시 지시어 없이도 상세응답 허용(새재료·추천신호 제외) | ✅ 배포 |

### 5. 재료 NER (CRF) — 🟢 서빙 개시 (2026-07-29, 레시피 구조화)
**결정:** 약지도 라벨링(EPIS gold 사전 → COOKRCP01 자동 라벨) → CRF 학습. **오프라인 학습 아티팩트**(PG는 1회 스냅샷만).
**중요:** 프로덕션 챗은 `EXTRACTOR_BACKEND=rule`로 서빙 — **챗에는 CRF 미투입**(분포 불일치).
**단 CRF 자체는 2026-07-29 서빙 개시** — 정당한 용도인 *레시피 `ingredient_raw` 구조화*에 투입했다.
`pipelines/ingest/backfill_ner_raw_ingredients.py`:
- 크롤러가 못 쪼갠 `ner_status='RAW'` 덩어리 **1,143 레시피**는 `item_id` 가 하나도 없어 **재료비·재고매칭·추천·랭킹 어디에도 안 잡히던** 상태였다(재료가 없는 것과 같았다).
- CRF 로 구조화 → **재료 12,662개 추출 · item_id 매칭 97.1% · 분량 확보 92.3%**. **레시피 1,142개가 되살아났고** 전체 재료 매칭률이 92.5%→**93.2%** 로 올랐다.
- ⚠️ **줄바꿈 오염 실측**: 제목과 첫 재료가 붙어 `'새우두부계란찜\n연두부'` 가 한 스팬으로 나왔다(학습 땐 제목줄을 마스킹하지만 추론 경로엔 없었다). **줄 단위 처리 + 헤더줄 제거**로 해소.
- ⚠️ **분량은 재료명 직후 계량만** 받는다. 스팬 사이를 통째로 쓰면 레시피 제목이 분량으로 딸려온다 — 틀린 분량은 재료비를 그대로 왜곡하므로 **애매하면 비운다**.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| CRF는 레시피 분포 학습→채팅 적용 시 과다추출 | **채팅은 rule 유지**(CRF 스왑 금지). CRF는 레시피 코퍼스 정규화용 | ✅ 결정 |
| 레시피 코퍼스 정규화에 CRF 미투입 | RAW 덩어리 백필 배치로 **서빙 개시**(위) | ✅ 2026-07-29 |
| 사람 라벨 0건 | 약지도(gold 사전 자동라벨)로 대체 | ✅ |
| 채팅용 대화체 NER 학습데이터 없음 | **실측 결과 불필요** — rule F1 0.990 > CRF 0.620 > 생성형 0.533. 생성형은 없는 재료를 창작해 추천 입력을 오염시킨다 | ✅ 2026-07-29 |

### 6. 관심재료 최저가 알림 — 🟢 구현 완료 (2026-07-29)
**결정:** 관심등록 재료 → 그 재료 상품만 비교(역방향 스코프). 용량 티어 수작업 대신 **±30% 크기밴드** 비교. **합성금액 금지** — 화면엔 실상품+실가격+용량+시점, 문구 "이 크기에서 찾은 최저가(N시 기준)".
**실 DB 검증(2026-07-24, 읽기전용):** 매칭 kurly 87.3%/oasis 91.7% · **두 마켓 overlap 237개(63.7%)·고빈도원물 92%** · 100g 비교가능 204개 · 동일크기 비교 84% · 단가노이즈 5% · 매칭정밀도 ~91%(LLM채점). **`retail_item_price_compare` 뷰가 양마켓 100g를 이미 계산.**

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| 품목 인식률 낮음(복합·가공품) | 관심재료 역방향 스코프(전 카탈로그 분류 안 함) | ✅ 결정 |
| 100g 단가비교 함정(벌크 1등) | 기준크기 ±30% 밴드 내에서만 비교 | ✅ 결정 |
| 오아시스 데이터 부재로 overlap 미측정 | 실DB로 측정→**63.7% 성립 확인**(막힌 벽 해소) | ✅ 검증 |
| 공식 기준선(price_online_daily) seed | **4 item만 커버→무용, 폐기**. 크롤 자체 이력으로 baseline | ✅ 결정 |
| 액상(volume_ml) 파싱 | 100g 비교 불가 — **실측 규모 21개 품목**(ml 단가만 있고 100g 없음). 별도 축(`won_per_100ml`)이 뷰에 이미 있어 필요해지면 확장 가능 | ⬜ 한계(소규모) |
| 육류혼동·가공품 오매칭(~9%) | 원물 스코프 + item_master.category 가드(가공/세트 제외) | ⬜ 설계 |
| 롱테일 콜드스타트 | 인기원물은 크롤이력 충분, 롱테일만 관측누적 대기 | ⬜ 수용 |

### 7. 영상→레시피 추출 — 🟢 구현 완료 (2026-07-29)
YouTube URL → Gemini 멀티모달 추출 → RecipeExtraction. 추출 `gemini-3.5-flash-lite` / 하드실패 재분석 `gemini-3.5-flash` / 정제 기본 OFF(비용). 영상토큰이 비용 90%+ → 1차는 최저가 모델 원칙.

**완료 내역**(#11 과 같은 기능이라 함께 마감):
- `services/video` 서비스화 — FastAPI + Redis 잡스토어(처음부터 replica-safe, #298) · 단일비행 락 · 교차유저 캐시(TTL 30일, 재요청 비용 0).
- **H0(영상 미수신) 구분** — 환각 응답이 유저에게 나가는 경로 차단.
- **H4 간헐 실패 해소** — 하드실패 5/6 → **0/6**, 재분석 0회. 원인은 타임스탬프가 아니라 **채점 규칙 자체**였다(길이 초과를 하드→소프트로 강등 + 국소 보정).
- **NER 정규화 배선** — 추출 재료에 `item_id` 를 채워 재료비·재고매칭에 연결(실 영상 9/10 매칭).
- **인분 미상은 추정하지 않는다**(`servings_known=false`) — 틀린 인분은 재료비를 그대로 왜곡.
- **경로를 api-spec #24·#25 계약(`/api/recipes/extract`)에 정렬** — 서비스가 `/api/recipes/video` 로 내고 있어 프론트가 붙는 순간 404 가 날 자리였다. 게이트웨이 라우팅 추가.
- 테스트 22 passed.

## 횡단 결정 (인프라·거버넌스)

### 🆕 Vertex AI 리전 = **`global`** (결정 2026-07-30, 팀 승인)

OCR·영상의 Gemini 호출을 Vertex 로 옮길 때 **글로벌 엔드포인트를 쓴다** — 즉 **영수증 이미지가
국내 리전 밖에서 처리되는 것을 수용**한다.

**레지던시를 포기한 것이 아니라 선택지가 없었다.** 채택 모델 `gemini-3.5-flash-lite` 가
**리전 엔드포인트에 아직 배치되지 않았다**(실측: 서울 `asia-northeast3` · 도쿄 · us-central1
전부 **404**, `global` 만 응답). 모델이 없는 것이 아니라 리전에서 서브되지 않는 상태다.

따라서 서울 고정은 "+10% 할증" 문제가 아니라 **모델을 구세대로 낮춰야 하는** 문제이고, 그러면
채택 근거(실물 13장·성공률 92%·0.45원/장)가 전면 무효가 되어 재벤치마크가 선행된다.

- **재검토 트리거**: 서울 리전에 모델이 배치되면 `GCP_LOCATION` 한 줄로 전환 가능(코드 변경 없음).
  확인법·비교 기준 = `gcp-migration-plan.md` §7-1.
- **별도 확인 사항**: 개인정보 처리방침의 **국외 이전 고지** 필요 여부(법무·심사 영역).
- 코드에 `GCP_LOCATION` **기본값을 두지 않았다** — 리전이 레지던시를 결정하므로 조용히 아무
  리전에 붙는 일이 없어야 한다(미지정이면 기동 실패).

### 🆕 모델 선택 규칙 — **태스크 유형으로 판단** (실측 2026-07-28, 누적 ~1,750건 · 15모델)
신규 AI 기능을 만들 때 **서비스 단위가 아니라 태스크 유형**으로 모델을 고른다. 근거: [`ai-model-migration-benchmark.md`](./ai-model-migration-benchmark.md)

| 태스크 유형 | 모델 | 실측 근거 |
|---|---|---|
| **분류·라벨링**(감정·카테고리·의도) | ✅ **Bedrock `nova-micro`**(서울) | 감정 24/25 ≈ Gemini 25/25 · 2.2× 빠름 · 절반 비용 |
| **텍스트→구조화 JSON 추출** | ✅ **Bedrock `nova-micro`**(서울) | 품목 100%·합계 25/25 · 0.031원 · 469ms |
| **한국어 문장 생성 — 근거 재작성**(refine) | ✅ **Bedrock `nova-micro`(서울)** | 숫자보존 프롬프트 시 **프로덕션 경로 20/20 = Gemini 동률**(실험 G) |
| **한국어 문장 생성 — 자유 요약/서술** | ✅ **`claude-3-5-sonnet-v2`(서울)** 확정 | 실측(2026-07-29): 존댓말 지시 준수가 갈랐다 — nova-micro 1/8 · **haiku-4.5 0/8** · 3-haiku 8/8(장황) · **3.5-sonnet 8/8·2.0문장** · sonnet-4.5 7/8(장황·느림). **신형이 항상 낫지 않다** |
| **한국어 이미지 판독**(OCR) | ❌ **Gemini 유지(확정)** | Nova 통짜 환각 · claude-3-haiku 글자 오독 |
| **영상 이해** | ❌ **Gemini 전용** | Bedrock에 유튜브 URL 입력 없음 |

- **왜 이렇게 갈리나**: Nova는 **한글 글자를 생성·판독하는 데 약하고**(OCR 환각, 텍스트에서도 "대파"→"냠파"), **입력 텍스트를 읽고 라벨·구조를 뱉는 데는 포화 품질**이다.
- **데이터 레지던시**: 도쿄 리전엔 GLM-4.7 등 더 강한 모델이 있으나(챗 Gemini와 동률) **한국 유저 데이터의 일본 반출**이라 팀 합의 전까지 사용하지 않는다. 리전 간 성능차는 41ms로 무의미 → **리전은 성능이 아니라 레지던시로 결정**.
- ✅ **액세스 개통·1차 재측정 완료(2026-07-29)**: `claude-haiku-4-5`·`claude-sonnet-4-5` 가 열려 실호출을 확인했고, **자유 요약 태스크로 5종을 정량 비교**했다(위 표).
  - ⚠️ **아직 요약 태스크만 쟀다.** 챗 refine·OCR·분류 판정을 바꾸려면 **각 태스크의 동일 케이스로 재측정**해야 한다 — 요약 결과를 전용하지 말 것(이번에 nova-micro 가 refine 동률인데 요약은 실패한 것이 그 증거다).
  - 📌 **얻은 규칙**: **신형이 항상 낫지 않다.** `haiku-4.5`(존댓말 0/8) < `haiku-3`(8/8). 세대가 아니라 **태스크별 실측**이 판단 근거다.

- **Gemini 모델 전면 3.5 핀 고정**(별칭 드리프트 근절, PR #272) — `-latest` 금지, 폐기 시 404로 즉시 인지. 유료예외(팀 재승인).
- **회원가입 일괄 통합 동의** → 대화·행동 데이터 영속·개인화·리포트 활성.
- 챗 프로덕션 플래그(ON): 멀티턴 · 계정연동 · 대화영속 · 냉장고읽기 · 대화일관성.
