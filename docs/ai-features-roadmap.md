## 운영·구현된 기능 (결정 + 한계 + 해결)

### 1. RAG 챗봇 "밥풀이" — 🟢 운영
**결정:** 5단계 파이프라인(①질문분석 ②병렬검색 ③컨텍스트조립 ④생성 ⑤응답조립). Gemini refine은 **레시피 추천만** 다듬음(가격·영양은 template = 0원·환각0). 멀티턴(Redis), 가드레일 4층, 제외재료 마이페이지 영속, 냉장고 재고 읽기, recipe-in-focus 대화일관성.
**구성요소:** 의도분류(`extract._classify_intent`, 규칙 nutrition/recipe_cost/recommend/price + ML 보강 opt-in)는 ①단계 라우터 — template(④생성)과 별개.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| 냉장고 재고를 못 읽음(StubPantry) | **chat→pantry API 위임**(재료 미지정 추천 시 재고 item_id 주입) | ✅ 배포 |
| 후속발화가 직전 답 반복 | **반복 가드**(동일답 억제) + **recipe-in-focus**(선택 요리 상세응답) + 확인발화 소셜응답 | ✅ 배포 |
| 영양소 질의가 가격으로 오분류 | nutrition 키워드 보강(나트륨·지방·탄수화물 등) | ✅ 배포 |
| "그거 재료/몇분/칼로리" 드릴다운 이탈 | 초점(focus) 활성 시 지시어 없이도 상세응답 허용(새재료·추천신호 제외) | ✅ 배포 |
| 비요리 발화→유튜브 폴백 오발동 | 폴백 발동조건 조이기(요리명 신호 필요) | ⬜ 계획(3안) |
| 냉장고 pantry 소스 자체는 여전히 stub | 위임으로 우회(소스 실구현은 후속) | 부분 |

### 2. 영수증 OCR/Vision — 🟢 운영
**결정:** Gemini Vision 단독(팀장 결정). 실물 13장 벤치마크로 flash-lite 채택(92%·0.45원/장). classify 캐스케이드, shelf_life_ref DB 로드, 경계정책(생수·얼음·홍삼정) 코드 상수.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| `-latest` 별칭이 3.x로 롤링→thinking_budget=0 거부(400) | 모델을 **gemini-3.5-flash-lite 버전 핀** + thinking=1(사실상 off) + 400시 폴백 | ✅ 배포 |
| 세대 변경으로 벤치 수치 재확인 필요 | 3.5 기준 장당 단가 재벤치(경미) | ⬜ 여유시 |

### 3. 개인화 레시피 랭킹 — 🟢 운영(콜드스타트)
**결정:** 규칙순 P0 → **LightGBM LambdaMART P1**. mealplan 종속, pantry seam(재고 커버리지·임박재료). 재학습→`/reload` 훅으로 서빙 자동반영. 인기도 피처 = recipe_popularity(삭제누적) + user_event(보존창) 합산.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| 학습데이터 부족(콜드스타트) | 데이터 임계 전엔 규칙순 폴백 | ✅ 동작 |
| lightgbm libgomp.so.1 부재(python:slim) | Dockerfile에 libgomp1 설치 + 로드실패 폴백 | ✅ 배포 |
| 클릭스트림 축적 필요 | events.user.activity 토픽·컨슈머(1.1.4 릴리스로 해소) | ✅ |

### 4. 대화분석 (chat-insights) — 🟢 운영
**결정:** daily/threshold 리포트(구조화 지표 + Gemini 서술). 회원가입 일괄동의 기반 `chat.chat_message` 영속을 입력으로.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| chat_message에 FK/cascade 없음→유저삭제 시 고아 | 삭제권(D-3)은 cascade 대신 명시적 삭제/보관정책 필요 | ⬜ 이슈 #273(데이터팀) |

### 5. 재료 NER (CRF) — 🟡 구현·미서빙
**결정:** 약지도 라벨링(EPIS gold 사전 → COOKRCP01 자동 라벨) → CRF 학습. **오프라인 학습 아티팩트**(PG는 1회 스냅샷만).
**중요:** 프로덕션 챗은 `EXTRACTOR_BACKEND=rule`로 서빙 — **CRF 미투입**.

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| CRF는 레시피 분포 학습→채팅 적용 시 과다추출 | **채팅은 rule 유지**(CRF 스왑 금지). CRF는 레시피 코퍼스 정규화용 | ✅ 결정 |
| 사람 라벨 0건 | 약지도(gold 사전 자동라벨)로 대체 | ✅ |

### 6. 관심재료 최저가 알림 — 🔵 실현가능성 검증 완료(미구현)
**결정:** 관심등록 재료 → 그 재료 상품만 비교(역방향 스코프). 용량 티어 수작업 대신 **±30% 크기밴드** 비교. **합성금액 금지** — 화면엔 실상품+실가격+용량+시점, 문구 "이 크기에서 찾은 최저가(N시 기준)".
**실 DB 검증(2026-07-24, 읽기전용):** 매칭 kurly 87.3%/oasis 91.7% · **두 마켓 overlap 237개(63.7%)·고빈도원물 92%** · 100g 비교가능 204개 · 동일크기 비교 84% · 단가노이즈 5% · 매칭정밀도 ~91%(LLM채점). **`retail_item_price_compare` 뷰가 양마켓 100g를 이미 계산.**

| 한계점 | 결정된 해결방법 | 상태 |
|---|---|---|
| 품목 인식률 낮음(복합·가공품) | 관심재료 역방향 스코프(전 카탈로그 분류 안 함) | ✅ 결정 |
| 100g 단가비교 함정(벌크 1등) | 기준크기 ±30% 밴드 내에서만 비교 | ✅ 결정 |
| 오아시스 데이터 부재로 overlap 미측정 | 실DB로 측정→**63.7% 성립 확인**(막힌 벽 해소) | ✅ 검증 |
| 공식 기준선(price_online_daily) seed | **4 item만 커버→무용, 폐기**. 크롤 자체 이력으로 baseline | ✅ 결정 |
| 액상(volume_ml) 0% 파싱 | 액체류 100g비교 불가(한계로 남김) | ⬜ 한계 |
| 육류혼동·가공품 오매칭(~9%) | 원물 스코프 + item_master.category 가드(가공/세트 제외) | ⬜ 설계 |
| 롱테일 콜드스타트 | 인기원물은 크롤이력 충분, 롱테일만 관측누적 대기 | ⬜ 수용 |

**미구현분:** `price.price_watch` CRUD + 뷰 델타 감지 → `notify.notification(LOW_PRICE)` 발행.

## 로드맵 (예정 · 결정됨)

### 7. 영상→레시피 추출 — 🟠 2026-07-24 착수
YouTube URL → Gemini 멀티모달 추출 → RecipeExtraction. 추출 `gemini-3.5-flash-lite` / 하드실패 재분석 `gemini-3.5-flash` / 정제 기본 OFF(비용). 영상토큰이 비용 90%+ → 1차는 최저가 모델 원칙.

### 8. 이상징후 탐지 대시보드 — ⬜ 예정
**인프라/클라우드 담당자용.** AI+모니터링(Prometheus/Grafana 계열)으로 인프라 이상 감지. 부하테스트는 이 트랙과 병행(베이스라인 확립·탐지기 검증·임계 캘리브레이션)이 정석.

### 9. 가격 이상치 탐지 — ⬜ 예정
ai-spec §2 "최저가 이상탐지"(자체 통계·z-score/baseline). 6번(최저가 알림)의 비교 인프라·크롤이력을 재사용. RAG·개인화·OCR 완료 게이트였으나 로드맵 편입.

### 10. 리뷰 감정분석 — ⬜ 예정
**만개의레시피 리뷰데이터** 사용. 출력: **긍정 비율(%)** 표시 + 리뷰 종합 **2~3문장 요약**. LLM(Gemini) 요약 활용.

### 11. 유튜브 영상분석 — ⬜ 예정
영상 콘텐츠 분석(7번 영상→레시피와 연계 가능).
