## 방법 (실측)

- **소매**: `retail_product.name` distinct **4,811** (retail 정규화 래퍼 `make_retail_matcher` 경유, 재료스코프 = `is_non_ingredient` 제외).

측정 스크립트는 현재 스크래치패드(throwaway) — 확정 시 `pipelines/ingest/`로 승격 예정(cf. `measure_coverage.py`).

## ③ prefix strip — 실측 결론: **"원칙 금지"는 과잉, 유지가 옳음**

### 분포 (레시피, row-weighted)
| method | distinct | rows | |
|---|---|---|---|
| exact | 698 | 42,603 | 볼륨 85% |
| suffix | 1,328 | 3,504 | |
| token | 1,185 | 1,428 | |
| **prefix** | **431** | **1,529** | 제거 시 미매칭될 전량 |
| none | 634 | 947 | |

### prefix 431종 분해 (remainder = 이름 − prefix alias)
- **420 benign** — 벗겨지는 꼬리가 가공접미(가루 536행·캔·통조림·물·즙·국물·나물·채·면·주스…) → base 정규화 **정당**.
- **11 suspect**(실질 9) — 전부 **잼/밥/떡 granularity**(딸기잼→딸기 등). **간장게장급 파국 0.**

### 소매 (retail)
- prefix 재료스코프 **204행 / 전체 매치의 ~5.5%**. 교차오분류 의심 **20종 전부 x1**.
  - ~14 = 잼 granularity(레몬잼·블루베리잼…), ~6 = 진짜 파국급: `참기름김`→참기름(실은 김)·`명란김`→명란젓·`불고기햄`→소고기·`강황쌀`→강황·`귀리쌀`→귀리.

### 진단 — 파국의 뿌리는 prefix가 아니라 **head-final 붕괴**
`참기름김`의 머리 `김`은 진짜 아이템인데 **1자라 `len≥2` 가드에 막혀 suffix 실패 → prefix로 낙하**해 앞의 `참기름`을 주움. 즉 한국어 '머리=뒤' 우선이 깨진 것.

### 권고 (미확정)
- **(A) prefix 삭제 = 기각** — 레시피 420 + 소매 204 benign(≈624종) 파괴. 문서의 "prefix 원칙 금지"는 실측상 과잉.
- **fix = head-preference 게이트** — `remainder(꼬리)가 비-prefix 사다리로 아이템에 해소되면 그 머리를 우선`. → ②(수식어/머리 정책) + ④(짧은 별칭)에서 흡수. prefix 독립 수정 불필요.

## ④ 짧은 별칭 (연결)
`len≥2` 가드가 1자 머리명사(김·쌀·잣)를 suffix에서 차단 → prefix 낙하·오분류를 **유발**. 323개 ≤2자 별칭 감사와 함께 1자 머리 허용 정책 재검토 필요(③ 파국의 실제 원인).

## ⑤ granularity — 반복 결정거리
**잼**(딸기잼·블루베리잼·레몬잼…)이 레시피·소매 양쪽에서 반복. "과일잼을 과일로 롤업 vs `잼` 아이템 분리"는 매처가 아니라 **item_master granularity 결정**(오너). 밥/떡도 동류.
- **치즈 품종(체다·파마산·모짜렐라) — ⑤ 보존 확정(2026-07-17):** 가격비교상 품종별 가격차가 커 `치즈`로 뭉개면 안 됨. 무시가능 사전에서 제외, item_master에 품종 분리(또는 alias 정책) 필요.

## ② suffix 수식어 정책 — 실측 결과

suffix 워크호스(레시피 **1,328종**). 각 매치의 modifier(=벗겨진 앞부분)를 실측.

### modifier 빈도표 → 두 부류가 명확
- **무시가능(조리·형태·가공, resolves=N):** 다진(52)·삶은(20)·냉동(17)·채썬(16)·마른·건·굵은·송송썬·슬라이스·갈은·고운·볶은·찐·구운·깐·데친·말린·불린… → 벗겨도 됨(다진마늘→마늘). **suffix 대다수가 여기 = 정상 동작.** → 무시가능 접사 사전(아래 정책 1).
- **의미보존(resolves=Y):** 소고기·돼지고기·참치·밀가루·쌀·계란… = 실체 재료.

### identity-loss 의심 245종 → 클래스
| 클래스 | 예(빈도) | 처리 |
|---|---|---|
| 동물(육류) | 돼지고기다짐육→다짐육(33)·소고기다짐육·목살·앞다리살 | #54 가드 일반화 |
| **수산 어종 ★NEW** | **참치액젓→멸치액젓(44)**·멸치육수→육수(36)·다시마육수 | #54의 수산 확장 — 액젓/젓/육수 어종 소실·혼동 |
| 종류/품종 ⑤ | 배추김치→김치(20)·열무김치·오이고추→고추(11)·쌀국수→국수·보리새우→새우 | granularity 오너결정 |
| 파국(데이터버그) | 고추냉이→냉이(5, **와사비인데!**)·닭다리살정육→소고기(3, **닭인데 소!**) | 아이템추가/alias수정 |
| benign | 옥수수전분→전분·토마토케찹→케첩·고추참치→참치 | OK |
| 파싱노이즈 | 참기름 또는 들기름→들기름 | "A 또는 B" 분리(별개) |

### 도출 정책 (미확정)
1. **무시가능 접사 사전** — 조리/형태/가공 morpheme 화이트리스트(cf. `retail_norm.py`의 MOD·NOISE_TOK 선례). suffix collapse 유지.
2. **종 세분화 = 동물(코드 가드) + 수산(데이터)** — 동물은 #54 가드 채택(→`gazetteer.py`), 수산은 종별 액젓 등 item 데이터 픽스(아래 실측). 참치액젓 x44.
3. **종류/품종 ⑤** — granularity 오너 결정.
4. **alias 위생** — `정육→소고기`·`훈제→오리고기` 등 과잉 alias 정리(파국 일부의 진짜 원인, `curate_item_master.py`).

### 무시가능 접사 사전 (정책1 — 확정 2026-07-17)

suffix collapse가 **안전한**(벗겨도 정체성 불변) modifier morpheme. 종세분화 가드(정책2)의 안전목록.
⚠️ `resolves=N`을 그대로 쓰면 안 됨 — 품종어(체다·파마산 등)는 gazetteer 미등재라 resolves=N에 섞여 들어옴(→ ⑤ 보존). 아래는 **큐레이션 확정본**:

### 정책2 종세분화 — 동물(코드) / 수산(데이터)로 갈림 (실측 2026-07-17)

수산 실측(item_master 수산물 **75**·육류 42, 코퍼스 전수): 육류식 "부위+종 → 종고기 remap" 구조가 **수산엔 없음**(생선엔 갈비/다짐육 같은 부위-종 구조 부재). harm이 **제품형 generic head**에 집중 → 데이터 큐레이션 문제.

| head(제품형) | 빈도 | 예 | 처리 |
|---|---|---|---|
| 멸치액젓(액젓 rollup 타깃) | 53 | **참치액젓→멸치액젓 x44**·꽃게·새우액젓 | **DATA ⑤ — split(참치액젓 신규 item→exact 우선) vs rollup 유지(아래)** |
| 육수(cross-category) | 61 | 멸치·다시마·소고기·버섯 육수 | ⑤ 저우선(육수 base 대체로 허용) |
| 다시다 | 7 | 소고기·멸치·조개 다시다 | ⑤ 저우선 |

**결론: 정책2 = 동물(코드 가드, #54 채택→`gazetteer.py`) + 수산(데이터 큐레이션, 액젓 중심).** 메커니즘 상이.
⚠️ **정정(중요):** 액젓/육수 collapse는 버그가 아니라 `curate_item_master.py`의 **의도적 rollup** — `"액젓":"멸치액젓"`·`"까나리액젓":"멸치액젓"`(L81·88), `"사골/해물/야채/치킨육수":"육수"`(L87). 즉 참치액젓→멸치액젓은 현행 granularity와 **일관**. 코퍼스 실volume은 사실상 **참치액젓(49)**뿐(꽃게·새우액젓 x1). → **결정(오너 ⑤):** ⓐ 참치액젓 **split**(신규 canonical → exact가 액젓 suffix 이김) vs ⓑ rollup 유지 + canonical `멸치액젓→액젓` **오칭 교정**(rename).

생선-head 오탐(훈제연어→연어·김밥용김→김)은 매칭 아니라 **alias 위생(정책4)** 문제 — 아래 실측 참조.

**✅ ⓐ 적용(2026-07-17):** `CATS["양념"]`에 `참치액젓` canonical 추가 → `참치액젓`·`참치 액젓` exact 매칭 확인(멸치·까나리·바 액젓 rollup 불변). ⚠️ 이 코드 변경이 #134 머지에서 누락(Commit D stranded)돼 **DB(item 4027)만 반영·code drift** → 본 alias-hygiene 브랜치에서 복구.

### 정책4 alias 위생 — 제거 영향 실측 (2026-07-17)

후보 alias를 gaz에서 빼고 코퍼스 재매칭(before→after). **가설("과잉 alias 제거")이 대체로 기각:**

| alias | 제거 영향 | 판정 |
|---|---|---|
| `국거리→소고기` | retail **24 (전부 한우 국거리 = 정답)** | ✅ **KEEP** — 제거 시 정답 24 파괴 |
| `정육→소고기` | 닭/오리 정육 오답 ↔ 한우 정육 정답 (mixed) | **정책2 동물(가드) 소관** |
| `훈제→오리고기` | 훈제연어·족발 오답 ↔ 건강한오리훈제 정답 (3, mixed) | 정책2 / `오리` alias |
| `김밥용→햄`·`산적용→소고기` | 0 | 죽은 alias(무해) |
| `잡채용→소고기` | 돼지고기잡채용→돼지고기 1 개선 | 미미 |

**결론:** alias 제거로 깔끔한 win 없음. `국거리`는 정답이라 유지, `정육/훈제`의 종-애매성은 "generic head + 종 수식어" = **정책2 동물(meat guard)로 흡수**. 정책4는 사실상 정책2로 수렴.



## ① exact/최장 우선
현재 exact 선행 + 각 칸 최장 우선 이미 존재. head-preference 게이트 도입 시 우선순위 재정의 여지만.
