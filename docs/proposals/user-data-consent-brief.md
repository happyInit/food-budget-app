# 유저 데이터 수집 — 동의·팀 승인 결정 브리프

> **작성:** 건우 (AI 담당) · 팀 회의 결정용
> **상태:** 제안·옵션 정리 (미확정 — 결정은 팀). 아래 "AI 제안"은 참고 leaning일 뿐 확정 아님.
> **묶음 대상:** `user-behavior-data-request.md`(클릭스트림) + `chat-conversation-data-plan.md`(챗 대화)
> = **하나의 "유저 데이터 수집" 트랙**으로 함께 승인 요청.

## 1. 왜 이 결정이 필요한가

개인화(레시피 랭킹·챗봇 응답)와 챗봇 AI 리포트를 하려면 **유저 행동·대화 데이터를 영속 저장**해야 한다.
그런데 이 데이터는 민감정보(알레르기·예산·건강·선호)를 포함할 수 있어, **수집 동의 + 팀 승인** 없이는
저장을 시작할 수 없다. 두 문서(클릭스트림·챗대화)가 **동일한 동의 절차를 공유**하므로 따로 승인받지 말고
**한 트랙으로 묶어 한 번에** 결정하는 게 목적.

## 2. 이 게이트가 막고 있는 것 (동의 전/후)

| 상태 | 진행 가능 | 진행 불가 (동의 전제) |
|---|---|---|
| **동의 전** | 챗봇 **멀티턴 맥락**(Redis 무상태 세션, 영속 X, P0) — 인프라(I-1) 몫 | 영속 저장·개인화·리포트 전부 |
| **동의 후** | 위 전부 | — |

- 클릭스트림: `user_event`/`recipe_impression` 영속 → 개인화 랭킹(P1 LightGBM) 학습 데이터 축적.
- 챗대화: `chat.chat_message` 영속 → 개인화 + AI 일일/임계 리포트.
- **핵심:** 승인이 늦어질수록 개인화용 **누적 데이터 축적 시작이 늦어진다**(행동 데이터는 누적형이라
  수집 시작 후에도 유의미한 학습까지 시간 소요). 멀티턴 P0는 동의와 무관하게 지금 진행 가능.

## 3. 팀이 정해야 할 항목 (옵션 + trade-off)

> 아래는 **결정 대기 항목**. 각 "AI 제안"은 참고용 leaning이며 확정 아님.

### 3.1 수집 동의 범위·UX
- 옵션: (a) 옵트인 명시 동의(기본) — 미동의 유저는 무상태 유지 / (b) 기능별 세분 동의(행동/대화 분리).
- 논점: 학생 비상업·비공개 전제라 최소 침해 원칙. 삭제권("내 대화·활동 삭제") UX 포함 여부.
- **AI 제안(미확정):** 단일 옵트인 + 삭제권. 세분 동의는 MVP엔 과함.

### 3.2 보존기간
- 클릭스트림 원시 이벤트: **180일**(예시) 후 집계본만. 챗 원문: **90~180일** 후 집계·익명화.
- 논점: 짧으면 프라이버시·저장 유리 / 길면 학습·리포트 표본 유리. 데모·캡스톤 기간(8~9주) 대비 과하지 않게.
- **AI 제안(미확정):** 원문 90일 + 이후 집계·익명화 영속. (학기 프로젝트엔 180일 불필요할 수 있음.)

### 3.3 저장 방식 — 테이블 vs Kafka
- 옵션: (a) PG 테이블(`user_event`/`recipe_impression`/`chat_message`) 직접 + (선택)Kafka 인입 /
  (b) 챗 이벤트도 `events.user.activity` Kafka에 편입(인프라 재사용, I-4).
- 논점: 테이블 방식이면 챗은 Kafka 토픽·컨슈머 **불필요**(I-4 조건부). 클릭스트림은 Kafka→PG 패턴 유지.
- **AI 제안(미확정):** 챗은 테이블 직접(단순), 클릭스트림은 Kafka→PG.

### 3.4 Kafka 토픽 스키마 (클릭스트림)
- 옵션: **JSON**(단순·스키마리스) vs **Avro**(스키마 레지스트리·계약 강제).
- **AI 제안(미확정):** MVP는 JSON, 규모 커지면 Avro 승격.

### 3.5 AI 리포트 파이프라인 설정 (챗)
- 리포트 전달 채널: **Slack DM / GitHub 이슈 / 파일** 중 택1.
- `report_every_n` 임계: **1000 vs 10000** + 일일 리포트 시각.
- AI 분석 입력 수준: **원문 vs 집계/익명화** (유료 Gemini 외부전송이라 원문 최소화 권장).
- **AI 제안(미확정):** GitHub 이슈 채널 + `report_every_n=1000`(초기 표본 확보) + 집계/익명화 전송.

### 3.6 민감정보 특별취급
- 알레르기·예산·건강: 외부(Gemini) 전송 시 **집계/익명화 후** + **외부전송 고지**. 이견 없으면 확정만.

## 4. 승인 시 다음 단계 (참고)

승인되면 게이트 이슈(Track 1)에서 구현 태스크를 분할한다:
- (백엔드/데이터) `app_user`(+`activity_consent`,`consented_at`)·`pantry_item`·`expense`·`user_event`·
  `recipe_impression`·`chat.chat_message` 테이블 마이그레이션
- (데이터) Kafka `events.user.activity` 토픽 + 컨슈머(→PG) — 3.3/3.4 결정 반영
- (백엔드/프론트) 동의 UX·삭제권·3이벤트 produce + 동의 게이팅
- (AI) 노출 로그 produce(랭커)·학습 스냅샷 export·리포트 배치

> `design.md`(SSOT)는 이 브리프로 수정하지 않음 — 승인 후 별도 승격 절차.
