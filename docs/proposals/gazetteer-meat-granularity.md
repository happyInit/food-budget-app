# 제안 초안 — gazetteer 육류 종/부위 예외 처리 (품목 매칭 세분화)

> **상태: DRAFT / 제안 (미결정).** 이 문서는 검토·조율용 초안이며, 확정 시 `docs/design.md`
> (품목 스파인 / §10 서빙 게이트 인접)로 승격한다. 아래 "권고안"은 결정이 아니라 **검토용 추천**이다.
> **오너 조율 필요**: item_master = 태현 / 텍스트검색 레이어 = AI·검색 담당.
> 발단: AI팀 "소갈비를 갈비로 조회 시 돼지갈비 누출" 우려 검증 (2026-07-15).

## 0. 요약 (TL;DR)

- gazetteer suffix 매처가 **육류 종(種)/부위 수식어를 떼어내** `소갈비·닭갈비·LA갈비 → 갈비(1192)`로
  뭉갠다. 반면 `돼지갈비 → 돼지고기(10)`(exact alias), `등갈비·떡갈비`는 각자 품목 → **비일관**.
- **현재는 무력(inert)**: 서빙 게이트가 1192-태그 레시피를 전부 제외(ES 서빙셋 내 `ingredient_item_ids=1192` = **0건**),
  데모의 "갈비→닭갈비" 뒤섞임은 **nori 텍스트 검색** 때문이지 이 매칭 붕괴 때문이 아님(별도 이슈, §6).
- 그러나 **게이트 완화 / NER 배선 / item_id 조회 승격** 중 하나라도 일어나면 실오답으로 전환됨.
- **Blast radius 좁음(29종/38레시피)**, **nutrition 이미 coarse(육류 item당 1행)** → **경량 규칙 가드 + 소량 alias 큐레이션**
  이 비용 대비 적정. 종×부위 2계층 모델은 캡스톤 스코프상 과설계로 판단(§5-C).

## 1. 검증된 현상 (실측 2026-07-15)

매처(`make_matcher`, exact→suffix→token→prefix) 실제 출력:

| 질문/재료 | item_id | canonical | 방식 | 평가 |
|---|---|---|---|---|
| 소갈비 | 1192 | 갈비 | suffix | ⚠️ 종(소) 유실 |
| 닭갈비 | 1192 | 갈비 | suffix | ⚠️ 부위 아님(닭갈비=볶음요리)인데 갈비로 |
| LA갈비 | 1192 | 갈비 | suffix | ⚠️ 종 유실 |
| 소고기갈비살 | 1233 | 갈비살 | suffix | ⚠️ 종 유실 |
| 돼지갈비 | 10 | 돼지고기 | exact | ⚠️ 부위(갈비) 유실 + 위와 다른 경로 |
| 등갈비 | 1176 | 등갈비 | exact | ✅ 자체 품목 |
| 떡갈비 | 1193 | 떡갈비 | exact | ✅ 자체 품목 |
| 한우 | None | — | — | ⚠️ 미매칭 |

**근본 원인**: (a) `item_alias`에 소갈비·닭갈비·LA갈비가 **없어** suffix 규칙이 접두어를 떼어냄,
(b) item_master가 육류를 **종 단위로 구분하지 않음**(generic "갈비" 버킷 1192),
(c) 큐레이션 비일관(돼지갈비만 별도 alias). **AI/학습과 무관** — 전부 결정론적 규칙.

## 2. Blast radius & 다운스트림 (실측, 규모 판단 근거)

- **species 접두어 + 육류 suffix 붕괴 = 고유 재료명 29종 / 38 rows / 38 distinct recipes.** (전체의 극소수)
- 파생 비일관도 관찰(별개지만 관련): `등심·불고기` alias가 소고기(26)를 가리켜 `돼지고기 등심 → 소고기`
  같은 **종 오매칭**도 존재 → 이번 예외 설계에 함께 태울지 결정 필요(§7 Q3).
- **다운스트림 커버리지** (신규 세분품목 비용 판단):

| item_id | 라벨 | food_nutrition | recipe_ingredient | retail_product |
|---|---|---|---|---|
| 1192 | 갈비 | **1** | 6 | 60 |
| 10 | 돼지고기 | **1** | 251 | 121 |
| 26 | 소고기 | **1** | 320 | 294 |
| 1176 | 등갈비 | 1 | 19 | 14 |
| 1233 | 갈비살 | 1 | 1 | 24 |

→ **nutrition은 이미 item당 1행(coarse)** 이라 세분 신규품목은 영양 orphan 위험. price(retail)는 커버리지 있음.

## 3. 왜/언제 문제가 되나 (트리거)

현재 무력이나 아래 중 하나라도 발생 시 **실오답**으로 전환:
1. **게이트 완화**(§10 미채택 ≥0.8 옵션 등) → 1192-태그 레시피가 서빙셋에 재진입.
2. **NER(CrfSpanExtractor) 배선** → 질문/재료 스팬이 늘어 매처 호출이 서빙 경로에 더 노출.
3. **item_id 기반 조회 승격**(가격/영양 조인, 재고 매칭, 레시피 랭킹 피처) → 붕괴된 item_id가 조인 키로 직접 사용.

## 4. 설계 목표 / 비목표

- **목표**: 소/돼지/닭/LA 갈비가 **서로 다른 item_id**로 (또는 최소한 서로 안 뭉개지게) 해소.
  종을 바꾸는 수식어를 **조용히 떼어내지 않기**. 다운스트림(영양·가격) orphan 최소화.
- **비목표(이번 스코프 아님)**: (a) §6 nori 텍스트 검색 누출 — 별도 이슈. (b) NER 구현. (c) 전 품목
  종×부위 정규화. (d) 도매/등급(한우 등급) 모델링.

## 5. 옵션 비교

### A. suffix 가드 (규칙만, 스키마 변경 없음)
매처에 **"종/종류 수식어" 세트**를 두고, `nc = 수식어 + alias` 이고 그 alias의 canonical이 육류면
**bare suffix 붕괴를 금지**(더 구체 alias 폴백, 없으면 None). 스케치:

```python
SPECIES_QUALIFIERS = {"소","돼지","닭","오리","양","한우","훈제","훈연","la","엘에이"}
# suffix 루프 내부:
prefix = nc[:-len(a)]
if prefix and _is_species_qualifier(prefix) and _canon_is_meat(a):
    continue        # 종을 바꾸는 붕괴 차단 → 더 구체 alias 또는 None
return gaz[a] + ("suffix",)
```
- **장점**: 코드 수 줄, 스키마 무변경, `소갈비/닭갈비` 무성 오매칭을 **즉시 차단**. 신규 미등록 복합어도 계열 차단.
- **단점/비용**: 매칭 실패분이 **None** 이 됨 → strict 게이트에서 해당 재료 든 레시피가 **non-servable로 탈락**
  (최대 ~38 레시피, 서빙셋의 ~1%). "틀린 매칭 vs 정직한 None"의 트레이드오프(§7 Q1).
- **위험**: 수식어 세트 과광범 시 정상 복합어 오차단(예: `양념갈비`의 `양념`은 종 아님 → 허용돼야 함).

### B. 구체 alias/품목 큐레이션 (데이터, 기존 패턴 확장)
`돼지갈비→10` 처럼 **의미 있는 부위를 명시 alias/품목화**. 두 갈래:
- **B1 신규 품목**: 소갈비·닭갈비·LA갈비 = 각자 item_id. 의미 명확하나 **영양 orphan**(§2) + 품목 증식.
- **B2 최근접 기존품목 alias**: 신규 품목 없이 가장 가까운 기존 item으로. 단 갈비 계열은 "종 보존"과
  "부위 보존"을 동시에 만족할 기존 품목이 없어 한쪽 유실 불가피(모델 한계 노출).
- **장점**: exact가 suffix보다 우선이라 가드 없이도 정확. 기존 큐레이션 패턴과 일관.
- **단점**: **화이트리스트라 미등록 신규 복합어는 여전히 붕괴**(계열 차단 불가). 큐레이션 유지비용.

### C. 종×부위 2계층 모델 (데이터모델 개편)
`recipe_ingredient`에 (부위 item + 종 facet) 또는 부모-자식 품목. 표현력↑.
- **판단: 과설계.** blast radius 29종·캡스톤 8~9주·nutrition 1행 구조 대비 ROI 낮음. **기록만, 보류.**

### D. 경량 조합 (A + 표적 B, 권고 후보)
`A(가드)` 로 **무성 오매칭을 명시적 None/구체매칭으로** 전환 + `B`로 **고빈도·다운스트림 있는 부위만** 소량 alias 큐레이션
+ item_master 종 세분은 §3 트리거 도달 시 재검토하도록 **백로그 기록**.

## 5.5 실측 결과 — 프로토타입 (throwaway, 2026-07-15)

`docs/proposals/proto_meat_guard.py` (읽기전용, 하드닝 최종본). 베이스라인 재계산 servable=**3169 = 라이브 ES와 일치**(재현 충실).

| 지표 | 현행 | A-block(None) | A-remap(종 item) |
|---|---|---|---|
| servable 레시피 | 3169 | 3109 (**-60**) | 3169 (**Δ0**) |
| 매핑 변경 고유재료명 | — | 32종 | 32종 |
| 실코퍼스 오매핑 도입 | — | 0 | **0** |

핵심 발견:
- **remap이 block을 압도**: 커버리지 손실 0 + 32종 전부 정상 교정. block은 60건(1.9%) 탈락하고 이득 없음
  (정상 재료가 None化). ⇒ **Q1 답: None(block)보다 remap(종 item 재매핑) 우위.**
- **가드의 실가치가 갈비보다 큼 — 교차종 버그 8건 교정**: `돼지고기 등심/불고기/잡채용`·
  `닭(고기) 정육/닭다리살 정육/닭정육`이 현행에 **소고기(26)로 오매칭**돼 있었음(pork/chicken→beef).
  remap이 돼지고기(10)/닭고기(7)로 교정. (갈비 계열 소갈비→소고기 등 species 보존도 동일 메커니즘.)
- **오발 1종(합성 테스트어에서만, 실코퍼스 0건)**: `양념갈비 → 양고기(2540)` — "양념"의 "양"을 sheep
  수식어로 오인. `양파·소금`은 육류 suffix가 아니라 가드 미발동(안전). ⇒ 프로덕션 가드는 단자 종수식어에
  **word-boundary/제외어**(양념…) 또는 bare '양' 제거 필요.
- **LA갈비 미커버**: 여전히 →갈비(1192). 명시 처리(LA→소) 또는 갈비 붕괴 허용 결정 필요(§7 Q2).

**하드닝 재측정** (`docs/proposals/proto_meat_guard.py`) — 위 2건 해소 확인:
- **`양념*` 오발 제거** (bare 단자 '양' 제거 + 제외어 양념/양파/양배추/소금…): 양념갈비→갈비, 양념불고기→소고기,
  양념돼지갈비→돼지고기, 양파/양배추 무영향. **실코퍼스 양념→양고기 오발 0종.**
- **LA/la/엘에이갈비 → 소고기(26) 커버** (단 실코퍼스 재료명엔 0건 = 견고성 목적).
- **32종 교정·servable Δ0 유지, 신규 오발 0.** 덤: `양고기 등심`(현행 소고기26 오매칭)→양고기(2540) 교정.
- **잔여 판단(§7 Q5)**: 순수 부위어(소갈비·LA갈비·소고기갈비살)의 **종보존(→소고기26) vs 부위보존(→갈비1192/갈비살1233)**
  트레이드오프 — nutrition은 종, price는 부위(rib)가 유리. 교차종 8건 교정과는 무관한 별도 curation 판단.

⇒ **가드 로직 검증 완료**: remap + 하드닝(bare양 제거·제외어·LA)으로 커버리지 손실 없이 교차종 버그 교정,
실코퍼스 오발 0. 구현 시 이 규칙셋을 `gazetteer.py`에 이식(오너 조율 후).

## 6. 인접 이슈 — 이번 제안으로 안 풀림 (명시)

데모의 "갈비→닭갈비" 뒤섞임의 **실제 원인은 nori 텍스트 검색**(`multi_match(name)` + 복합명사 형태소 분해).
gazetteer를 고쳐도 텍스트 누출은 그대로. **별도 검색 relevance 이슈로 분리**(query analyzer decompound,
phrase/정확 부스팅, 0건 시 Gemini 정직 안내). → AI·검색 담당 트랙.

## 7. 오픈 퀘스천 (결정 필요 — 임의로 정하지 않음)

1. **None vs 틀린 매칭**: ~~정직한 None vs 항상 매칭~~ → **실측(§5.5)으로 해소**: remap(종 item)이
   block(None) 대비 커버리지 손실 0(vs -60) + 교차종 버그 8건 교정. **remap 채택 권고.** 남은 결정은
   "remap 대상 종 item이 없는 경우(LA·훈제 등)만 None 허용할지".
2. **세분 단위**: 소갈비/닭갈비/LA갈비를 (a) 신규 품목 vs (b) 기존품목 alias 재배치 — nutrition orphan 감수 범위?
   돼지갈비(현 10)는 갈비 계열로 재배치할지 유지할지?
3. **범위**: 등심·불고기 종 오매칭(§2)까지 이번에 함께 볼지, 갈비 계열만 볼지?
4. **수식어 세트 소유권**: `SPECIES_QUALIFIERS`/EXCLUDE 를 코드 상수 vs `item_master` 메타(태현 관리)로 둘지?
5. **종 vs 부위(순수 부위어)**: 소갈비·LA갈비를 종보존(소고기26) vs 부위보존(갈비1192)으로 remap?
   교차종 8건 교정은 이 선택과 무관하게 정답. item_master가 1192='소갈비'로 특화되면 자연 해소(→B, 태현).

## 8. 권고 (검토용 — 미결정)

- **단기**: 옵션 **A(가드) + remap 모드** (실측 §5.5로 block 대비 우위 확인 — 커버리지 Δ0 + 교차종 8건 교정).
  가드 세부: 단자 종수식어에 **word-boundary/제외어**(양념…) 처리, `remap` 종 item 없는 LA·훈제만 잔여 결정.
  갈비 계열 신규 alias(B1)는 remap이 대부분 흡수하므로 **최소화**. 근거: blast radius 좁음 + nutrition coarse →
  경량이 적정, 종×부위 모델개편(C)은 ROI 낮음.
- **동시**: §6 텍스트 검색 누출을 **별도 이슈**로 분리 착수(데모 체감 문제의 실제 원인).
- **백로그**: item_master 종 세분화는 §3 트리거(게이트 완화/NER/item_id 승격) 도달 시 재검토.
