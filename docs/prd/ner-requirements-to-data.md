## Part 1. item_master / gazetteer 정리 요구

### 1.1 문제 (실측 케이스)

`gazetteer.make_matcher`가 **최장 접미 매칭**으로 육류 접두어를 떼어내 육류 구분이 붕괴·불일치한다.

| 입력 | 현재 매핑 | 방식 | 문제 |
|---|---|---|---|
| 소갈비 | item 1192 (갈비) | suffix (앞 "소" 제거) | 소(육류) 손실 |
| 닭갈비 | item 1192 (갈비) | suffix (앞 "닭" 제거) | **닭 요리를 소갈비뼈 품목에 오분류** |
| 돼지갈비 | item 10 (돼지고기) | exact alias | 갈비 정보 손실 + 소갈비와 **경로 불일치** |

→ 결과: 챗봇에서 "소갈비" 물으면 돼지·닭갈비가 섞이거나, 육류 종류가 뭉개진 표준코드로 조인됨. **표준 품목코드(조인키 척추, design §6.3)가 이 부분에서 육류 구분을 잃음.**

### 1.2 원하는 동작

동물+부위 복합 재료(갈비류 등)에서 **육류 종류가 코드에 보존**되어야 함. 아래 중 오너가 택일:

| 옵션 | 내용 | 트레이드오프 |
|---|---|---|
| **A (권장)** | `소갈비`·`돼지갈비`·`닭갈비`를 **각각 별도 item**으로 | 명확·조회 단순. 품목 수 증가 |
| B | **2축**(base=갈비 + animal=소/돼지/닭) 조합 모델 | 정규화 깔끔하나 스키마·매칭 로직 변경 |
| C (최소) | 별도 품목 없이, **alias만 올바르게** 부여 + suffix 매처가 **육류 접두어는 안 떼게** 예외 | 공수 최소. 단 "갈비"류 외 다른 복합어엔 재발 |

**공통 필수 (어느 옵션이든):**
1. `닭갈비 → 갈비(소부위)` 같은 **육류 오분류 제거** — 최소한 닭/돼지/소가 서로 안 섞이게.
2. **매칭 우선순위**: 등록된 정확 별칭(예: `소갈비`)이 있으면 **exact가 suffix-strip보다 우선** 하도록(현재 suffix가 먼저 잡음).
3. 경로 일관성: 소/돼지/닭갈비가 **같은 규칙**으로 매핑(지금은 소·닭=suffix, 돼지=exact로 제각각).

### 1.3 NER이 item_master에 요구하는 것 (일반 원칙)

- NER은 "문장 어디가 재료명인지"만 뽑음 → **그 span을 표준코드로 잇는 건 item_master/alias**. 즉 NER 성능은 **item_master의 커버리지·정확성에 상한이 걸림**.
- 요청: 실사용 재료(레시피·영수증에 나오는 표기)의 **별칭 커버리지 확대** + 위 육류 같은 **의미 손실 매핑 정리**. 우선순위는 빈도 높은 재료부터.

## Part 2. NER 학습 데이터 — 합의 항목

> 배경 변화: `ner-training-data-spec.md §0`의 우려("COOKRCP01이 10K로 덮여 삭제됨")는 **현 상태에서 상당 부분 해소**됨 — COOKRCP01/EPIS가 `recipe`에 적재돼 있고, **서빙은 이미 `source='10K'`만(#46)** 이라 앱 노출 위험이 없음. 남은 건 "학습용으로 안정적·원형 보존·접근"의 합의.

### 2.1 합의 필요 (택일/확인)

| # | 항목 | 요청 | 결정 |
|---|---|---|---|
| 1 | **원문 보존** | `recipe_ingredient.ingredient_raw`(COOKRCP01 자유텍스트)를 **정규화·축약 없이 원형 유지**. CRF가 문자 오프셋으로 라벨을 정렬하므로 다듬으면 학습이 깨짐 | 유지 확약 |
| 2 | **삭제·덮어쓰기 금지** | COOKRCP01·EPIS 행을 재적재/정리 시 **삭제하지 않기**. 서빙이 이미 격리하므로 앱엔 영향 없음 | 유지 확약 |
| 3 | **재적재 안전성** | 재적재 시 `ner_status='RAW'/'LABELED'` 행이 유실 안 되게 **레시피 단위 upsert**. 향후 사람이 검수한 라벨 보호용 컬럼(`labeled_at`,`labeled_by`) 여지 | 방식 합의 |
| 4 | **읽기 인터페이스** | 건우가 학습 시 데이터를 어떻게 받나 — ⓐ PG 직접 쿼리 ⓑ 시점 스냅샷(CSV/JSONL) export. 재현성 위해 **학습 시점 스냅샷 구분 장치**(타임스탬프 등) | ⓐ/ⓑ 선택 |
| 5 | **학습전용 테이블 분리** | 지금은 서빙 격리로 **급하지 않음**. 단 HITL 검수 라벨을 쌓을 계획이면 별도 테이블 or 위 3의 보호 컬럼이 깔끔 | 필요/불필요 |

### 2.2 건우 몫 (태현 작업 아님 — 공유용)

- EPIS와 COOKRCP01은 **서로 다른 소스라 `RECIPE_ID`로 조인 안 됨**(EPIS=정형 gold, COOKRCP01=자유텍스트, 별개 레시피). → 건우가 **EPIS 재료명을 사전으로 COOKRCP01 텍스트에 문자열 매칭해 약지도(weak supervision) BIO 라벨 자동 생성**. 이건 AI 쪽에서 진행하므로 태현에게 요청 없음.
- 10K(만개) 텍스트는 **학습 코퍼스로 사용 금지**(robots `ai-train=no`, `data-validation §2.2`) — 학습 추출 쿼리에서 `source != '10K'` 고정.

## Part 3. 우선순위 · 순서

1. **Part 2.1** (원문 보존·삭제금지·읽기 인터페이스) 확약 — 이게 있으면 건우 NER 착수 가능(데이터 이미 적재됨).
