## 0. 한 줄 요약

Gemini Flash-Lite를 **응답 다듬기(refine-only) 층**으로만 붙이고, 검색·근거조립·거절판정은 기존 TemplateGenerator가 담당. 실측 **신규 레시피 추천 1건당 ~0.06원**, 오프토픽·가격·영양·반복질문은 **0원**. 코드측 월 상한 **권장 7,200원**(Google 청구캡 8,000원의 90%) = 현실 최악(월 ~570원)의 **약 13배** 헤드룸이자 폭주 방지 브레이크. 기본 flag OFF.

## 1. 배경 — Gemini는 "다듬기"만, "생성"이 아니다

설계 원안(`chat-assistant-ai.md §2`)의 "LLM이 응답을 다듬는다" 층을 실제로 붙여 품질·비용을 실측.
```
추출 → DB 병렬검색 → 컨텍스트 조립 → TemplateGenerator(근거 조립 + 거절 판정) → Gemini 다듬기
                                                     └ 거절/skip이면 종료(호출 안 함)
```
- Gemini는 raw DB를 보지 않고 TemplateGenerator가 만든 **근거 텍스트만** 재작성 → 환각(없는 레시피·가격 지어내기) 원천 차단.
- 거절("모르겠어요")·95% 관련성 게이트는 TemplateGenerator에 있어 백엔드를 바꿔도 **정답률 동일**(`VALIDATION_LOG.md` iter5 = iter4 = 27/27). 근거 밖 숫자 생성 시 `check_output_grounded`가 잡아 template로 fallback.

## 2. 무료 티어 한계 (실측 — 유료 전환 근거)

| 모델 | 무료 티어 결과 |
|---|---|
| `gemini-2.5-flash-lite` | **404 NOT_FOUND** — "no longer available to new users" |
| `gemini-2.0-flash-lite` | **429 RESOURCE_EXHAUSTED** — 무료 쿼터 소진 |
| `gemini-flash-lite-latest`(별칭) | 호출되나 무료 RPM/RPD 제한에 걸림 |

무료 티어는 RPM·RPD가 빡빡해 피크타임(11-12·17-18시)이나 검증 스위트(연속 호출)조차 429 → **데모·실측 용도로도 부적합**. → 유료 전환(프리페이드 **16,000원** + Google 월 청구 상한 **8,000원**).

## 3. 비용 구조 (실측)

### 3.1 호출당 토큰·비용 (refine-only라 프롬프트가 작음)
| 구분 | 토큰 | 계산(Flash-Lite $0.10/$0.40 per 1M) | 비용 |
|---|---|---|---|
| 입력 | ~174 (시스템~120+질문~20+근거~35) | 174 × $0.10/1M | $0.0000174 |
| 출력 | ~71 (상한 200토큰) | 71 × $0.40/1M | $0.0000284 |
| **합계/호출** | | | **$0.000046 ≈ 0.06원** (₩1,380/$) |

> `chat-assistant-ai.md §4`의 초기 추정(입력 ~2,000토큰)은 풀 RAG 가정 — 실제 refine-only는 그 **1/10**.

### 3.2 실효 과금 최소화 — 3레버
| 레버 | 내용 | 효과 |
|---|---|---|
| ① 거절 skip | 오프토픽·무근거는 template floor가 거절 → Gemini 호출 안 함 | 오프토픽 **0원** |
| ② recommend-only | 가격·영양은 이미 깔끔한 구조화 사실 → 다듬기 skip, 레시피 추천만 호출 | 조회형 **0원** |
| ③ Redis 캐시(30일) | 동일 근거(grounded_text) 재질문은 캐시 반환 | 반복질문 **0원** |

추가: `max_output_tokens=200`, `temperature=0.3`(환각 억제), 타임아웃 8초 fallback. **→ 실효 과금 = "처음 나오는 레시피 추천 질문"뿐.**

### 3.3 지연 트레이드오프 (실측 `GEMINI_IMPACT.md`)
| 응답 유형 | template | gemini |
|---|---|---|
| 레시피 추천 | ~수십 ms | **~0.8~1.3초**(LLM 왕복) |
| 가격·영양·거절·반복질문 | ~수십 ms | ~수십 ms(호출 안 함, 동일) |
추천 응답에만 ~1초. 완화 = 캐시 히트·향후 스트리밍.

## 4. 예상 트래픽 시나리오 (호출당 0.06원)

| # | 시나리오 | 신규 추천 호출/월 | 비용/월 |
|---|---|---:|---:|
| A | 초기(데모·소수) | 수천 | 수백 원 |
| B | **현실**: DAU 500 × 어시스턴트 20% × 3회/일 × 캐시 50% | ~4,500 | **~285원** |
| C | 현실-최악: B에서 캐시 0% | ~9,000 | **~570원** |
| D | **성장 10×**: DAU 5,000 × 20% × 3회/일 × 캐시 0% | ~90,000 | **~5,400원** |
| E | 폭주(버그 무한재시도·스팸) | 수십만+ | 상한까지 |

정상 운영(B)=월 300원 안팎, 10배 성장(D)=~5,400원(아직 8,000원 미만). 상한이 의미 갖는 건 **E(폭주)뿐** → 상한 = "정상 제한"이 아니라 "폭주 차단". (달리 보면 현실 예상 월 300~600원의 **14~28배** 지점에 8,000원 청구캡이 있어 정상 운영에선 절대 안 닿는다.)

## 5. 월 상한값 선정 — 코드측 상한이 왜 또 필요한가

Google 콘솔 청구 상한 8,000원은 **billing 하드 스톱**(도달 시 API가 에러 → 코드가 template fallback). 문제: 경계에서 **불규칙한 실패**로 보이고 **강등 안내(배너) 없음**. → **코드측 상한**을 Google보다 먼저·의도적으로 걸어 일관된 배너("이번 달 이용량이 많아 간단 모드")를 제공(defense-in-depth).

### 5.1 밴드 도출
- **하한(넘겨야)** = 고성장 천장 D = ~90,000호출(~5,400원) — 여기 안 닿아야 정상운영 방해 X.
- **상한(밑이어야)** = Google 청구캡 **8,000원(≈127,000~133,000호출)** — 이 전에 강등해야 우아함+버퍼.
- → **밴드 = 약 5,400 ~ 8,000원.** **권장 7,200원**(청구캡의 **90%**, −800원 버퍼) ≈ **120,000 호출**.

| 기준 | 값 | 판정 |
|---|---|---|
| vs 현실 최악(C, 9,000) | 약 13배 | ✅ 정상 안 닿음 |
| vs 10배 성장(D, 90,000) | 약 1.3배 | ✅ 고성장 여유 |
| vs Google 청구캡(8,000) | 90%(−800원) | ✅ 하드스톱 전 강등 + 카운터 오차 흡수 |

**왜 90%(7,200)**: 코드 카운터는 Redis INCR라 동시요청·재시도로 실제 호출과 미세 오차 → 청구캡과 동일(8,000)이면 경계에서 Google 하드스톱과 겹칠 수 있어 **10% 아래**에서 먼저 끊음. **대안(허용)**: 청구캡 정렬 8,000원(100%)도 방어적으로 합당(단순·번호일치), 90%를 1순위.

### 5.2 민감도 — ₩예산 config면 자동 적응
| 변수 | 변화 | 영향 |
|---|---|---|
| 트래픽 | DAU 10× | ~5,400원(D) → 7,200 아래, 안 닿음 |
| 캐시 | 50%→0% | 호출 2배(C/D 반영) |
| 단가 | 0.06→0.12원(2×) | 예산제면 호출캡 자동 반감(120k→60k), 예산 7,200 유지 |
| 출력토큰·환율 | 71→200 / ₩1,380 변동 | 예산제면 자동 흡수 |

→ 상한을 "호출 수"가 아니라 **"원(₩) 예산"**으로 두면 단가·토큰·환율 변동에 **자동 적응**(호출카운터 × 실측단가 환산). 값 견고성의 핵심.

### 5.3 권장 config
```python
# 기본 OFF — 현 동작 보존, gemini 실서버 활성 시 ON
monthly_cap_enabled: bool = False
monthly_budget_won: int   = 7200          # Google 청구캡 8,000원의 90% (§5.1)
gemini_cost_per_call_won: float = 0.06    # 실측(§3.1). 요율·환율 변동 시 갱신
# 파생 호출 상한 = monthly_budget_won / gemini_cost_per_call_won ≈ 120,000
```
**동작**: 유료 refine 호출 시 Redis `chat:cost:{연월}` +1 → 요청 처리 전 `카운터 × 단가 ≥ monthly_budget_won`이면 template 강등 + 배너. 키 TTL ~35일(월 자동 리셋). 기존 일일 상한의 강등·배너 경로 재사용.

## 6. 5중 방어 (기존 안전장치와의 관계)
1. **구조적 최소화** — refine-only·거절 skip·recommend-only·30일 캐시 → 신규 추천만 과금.
2. **유저별 일일 상한**(구현됨, 200 req/일) — 한 사람 남용 차단.
3. **코드 월 예산 상한**(7,200원) — 전체 폭주 1차 브레이크(우아한 강등).
4. **Google 청구 상한**(8,000원) — 최후 하드 스톱.
5. **프리페이드 16,000원** — 상한 2개월치 버퍼, 자동재충전 서프라이즈 차단.

2·3은 코드, 4·5는 결제 인프라 — 축이 달라 상호 보완.

## 7. 가정·재검토 트리거
- ⚠️ **Flash-Lite 요율**($0.10/$0.40 per 1M)·환율(₩1,380/$)은 시점 변동 → 활성 전 현재가 확인, 변동 시 `gemini_cost_per_call_won`만 갱신(예산 원값 유지).
- 실측 토큰(174/71)은 현 프롬프트 기준 — 프롬프트 개편 시 재측정.
- **재검토 트리거**: DAU 3,000~5,000 지속(밴드 하한 근접) · 캐시 히트율 가정(50%) 이탈 · 요율/환율 유의 변동 · **Bedrock 이전**(비용이 크레딧 전환되면 상한 로직 목적 재정의).
