## 1. 용도 — 무엇을 하고, 무엇을 안 하는가

한 줄 정의: **"내 냉장고, 내 예산, 오늘 시세를 알고 답하는 식비 비서."** 범용 챗봇(ChatGPT)은 일반론("김치찌개가 저렴합니다")만 주지만, 이 챗봇은 유저 개인 상태를 검색해 "냉장고에 두부(내일 임박)·대파 있으니 두부조림, 부족한 건 간장뿐(오아시스 1,800원), 예산 잔여 충분" 같은 그 유저만의 답을 낸다.

**"앱 기능과 겹친다"는 비판에 대한 답 — 용도 3층 구조:**

| 층 | 응답 유형 | UI와의 관계 | 예시 |
|---|---|---|---|
| A | 기존 기능 프록시 | **겹침 (의도적)** | "뭐 해먹지?" → F16 추천을 말로 |
| B | 조합·해석 | **UI 제공 불가** | "임박한 두부 쓰면서 만원 이하, 매운 거 빼고" (임의 조건 조합) · "이번 달 식비 왜 늘었어?" (데이터 해석) |
| C | 생성 | **챗봇 전용** | "돼지고기 대신 닭고기로 하면?" — 레시피 변형+영양 변화(service-spec 기존 아이디어) |

A층이 겹치는 건 결함이 아니라 안전장치다 — 답의 근거가 전부 검증된 P0 기능에서 나오므로 환각 여지가 없고, 챗봇에만 있는 기능을 만들면 "챗봇 없으면 못 쓰는 기능"이 생겨 더 나쁘다. 정당성은 B·C층으로 방어한다: UI 필터는 미리 설계한 조합만 제공하지만(조건 n개 = 2ⁿ 화면) 챗봇은 임의 조합을 한 문장으로 처리하고, 해석·생성은 UI로 원천 불가능하다. A층의 독자 가치는 접근성 — "검색·필터를 다룰 줄 알아야 쓰는 앱"이라는 진입장벽 제거(해커톤 서사와 동일). 답변에는 [장바구니 담기]·[식단 추가] 버튼이 붙어 대화가 핵심 루프(추천→담기→장보기)의 입구가 된다.

**안 하는 것**: 잡담·요리 외 주제·자체 DB에 근거 없는 답변(근거 없으면 "모르겠어요").

## 2. 구성 — 5단계 파이프라인 (Chat Service, FastAPI · HPA)

```
"오늘 2만 원으로 뭐 해먹지?"
 ① 질문 분석   NER 엔드포인트 호출(재료→품목코드) + 규칙 기반 의도분류 + 예산·인분 파싱   [자체]
 ② 병렬 검색   asyncio fan-out 4소스: ES(레시피) · PG(냉장고·예산, JWT user_id 스코프)
               · PG(컬리·오아시스 가격 이력) · 영양 DB                                  [자체]
 ③ 컨텍스트 조립  검색 결과를 표준 품목코드(ING-xxxx)로 조인 → 프롬프트 주입              [자체]
 ④ 생성        Generator 인터페이스 (교체 가능 1개 층 — §3)                          [교체가능]
 ⑤ 응답 조립   문장별 근거 태그(가격 스냅샷 시각 등) + 액션 버튼 페이로드                [자체]
```

5단계 중 4단계(①②③⑤)가 자체 구현이다. **moat 축소 우려(§9)에 대한 입장**: RAG의 본체는 자체 NER·자체 데이터 검색·품목코드 조인·가드레일이고, 외부 LLM은 문장 조립 1개 층이다. 아래 §3의 템플릿 버전이 먼저 동작하면 "생성 없이도 답이 나오는 자체 파이프라인"이 증명되어 moat 논리가 오히려 강해진다. 원래 P2 설계의 FastText 의도분류도 ①단계에 추후 편입 가능(§5-① 로그 재사용).

## 3. 생성 백엔드 — 3단계 로드맵 (팀 결정 대기)

**설계 원칙**: 생성은 `Generator` 추상 인터페이스(입력: 조립된 컨텍스트+질문 / 출력: 답변+근거 목록) 뒤에 두고, 구현체를 환경변수(`GENERATOR_BACKEND=template|bedrock|gemini`, `GENERATOR_MODEL`)로 선택한다. 어떤 팀 결정이 나와도 ①②③⑤와 기존 구현은 버려지지 않는다.

| 시기 | 백엔드 | 비용 | 승인 |
|---|---|---|---|
| 지금 (온프렘) | **TemplateGenerator** — 검색 결과를 템플릿 문장으로 렌더 | 0원 | **불필요** (외부 API 호출 0 → AGENTS.md 절대제약 무관) |
| AWS 이전 후 | **BedrockGenerator** (Nova Lite, 필요시 Claude Haiku와 품질 비교) | AWS 크레딧 = 실질 0원 | 팀 승인 1회 |
| 옵션 | **GeminiGenerator** (Flash-Lite) | 월 ~$1 실사용, $10 하드 캡 | AGENTS.md 유료예외 확대 |

- ✅ **확정(2026-07-13)**: 1차 TemplateGenerator로 출시(무료·승인 불필요, §9의 Gemini 재승인 패키지와 무관). 실사용 품질 실측 후 부족하면 그때 Bedrock/Gemini 전환을 재검토 — 지금 시점엔 (a)/(b) 선택 자체를 보류.
- 유튜브 추출은 이 로드맵과 무관 — Bedrock은 YouTube URL 인제스트 불가라 그쪽은 Gemini 고정(기존 승인 범위).
- 로컬 CPU LLM은 채택하지 않음 — 품질 미검증이고, 템플릿이 이미 "승인 불필요한 기본 동작"을 제공해 중간 단계가 불필요.
- Nova Lite 한국어 품질은 미검증 → 이전 후 실질의 20개로 비교 평가(프롬프트는 컨텍스트 주입형이라 모델 교체 비용 거의 없음).

## 4. 비용 분석 (LLM 생성 시)

응답 1건 = 입력 ~2,000 토큰(시스템 프롬프트+검색 컨텍스트+질문) + 출력 ~300 토큰. Gemini Flash-Lite($0.10/$0.40 per 1M) 기준 **~$0.0003(약 0.4원)/응답**.

| 시나리오 | 규모 | 월 비용 |
|---|---|---|
| 개발·테스트 | 일 수십 질의 | < $1 |
| 부트캠프 현실 | 월 ~1천 대화 | $0.3~1 |
| 낙관 성장 (컨텍스트 4K 여유) | 월 1만 대화 | $6~7 |
| **하드 캡** | 유저별 일 상한 + 월 예산 상한 코드 강제 | **≤ $10** |

유튜브 추출 승인 전례(월 ~$44)의 1/40 규모. Bedrock Nova Lite($0.06/$0.24)면 월 1만 대화 ~$2 — 크레딧 대비 소수점 오차.

## 5. 템플릿 모드 품질 한계와 개선안

**층별 진단**: A층 체감 ~90%(답의 실체가 구조화 데이터, 문장은 포장) · B층 절반(조합 질의는 ①②③이 처리하므로 생존, **해석 질의는 사전 코딩한 패턴만** 가능) · C층 0%(승인 전까지 기능 숨김). 역설적 강점: 환각 0%·출력 가드레일 불필요·지연 수십 ms — 열세는 커버리지와 자연스러움뿐. **팀 내부 시연·개발용으론 충분, 대외 시연에서 "대화형 AI"로 내세우기엔 부족** → LLM 생성 전환(§3)이 대외 시연 전 필요.

**공통 품질 문제 3가지와 해결안** (LLM 전환 시 총 +1.5일):

1. **커버리지 절벽** (의도분류 실패 → "모르겠어요"): 3중 방어 — 규칙 분류(1차) → 미분류 시 **광역 폴백 검색**(재고+예산+추천 기본 세트를 검색해 LLM에 "이 범위에서 답하거나 못 한다고 하라") → 무응답 질문 전량 로그(`chat_unanswered` 액션, 클릭스트림 편승) → 주간 리뷰로 의도·매핑 추가. 이 로그가 축적되면 원 P2 설계의 FastText 의도분류기 학습 데이터가 됨.
2. **후속 질문 단절** (멀티턴): Redis 세션(user_id 키, TTL 30분)에 최근 3턴 + 직전 검색 컨텍스트 요약 저장 → 프롬프트 포함. "그럼 더 싼 건?"의 대명사 해소는 LLM이 이력으로 처리. 입력 토큰 +50%(0.4→0.6원, 무시 가능). 범위는 직전 주제 후속까지 — 세션 넘는 장기 기억은 개인화 랭킹의 영역으로 명시적 제외.
3. **기계성** (말투): LLM 생성으로 자동 해소. 템플릿이 폴백으로 동작하는 순간(장애·예산 캡)에는 "간단 모드로 답할게요" 문구로 기대치 조정 + 핵심 템플릿 5~6개 × 변형 2~3개 회전.

## 6. 가드레일 — 4층

1. **입력**: 주제 이탈·프롬프트 인젝션 패턴 필터, 길이 제한
2. **프롬프트**: 역할·범위 고정, "검색 결과 외 지식 사용 금지" 지시
3. **출력**: 응답 내 숫자(가격·수량)·품목코드를 검색 결과와 기계 대조 — 불일치 시 재생성/차단. 근거 없으면 답하지 않고 "모르겠어요"
4. **행동**: 액션 버튼은 검증된 엔티티만 — 만료 재고 제외, 실존 레시피만 담기 허용

(템플릿 모드에서는 3층이 구조적으로 불필요 — 문장 전체가 자체 코드 산출.)

## 7. 운영

- **비용 통제**: 유저별 일일 요청 상한 + 월 예산 상한(초과 시 템플릿 모드 강등 + 배너)
- **캐시**: 동일 유저 반복 질의 Redis 단기 캐시
- **폴백**: LLM 장애 시 TemplateGenerator로 자동 강등 — 생성이 죽어도 데이터는 나감
- **모니터링**: 응답 지연 p95 · 무응답률 · 가드레일 차단률 · 일일 비용 (기배포 Grafana 스택)
- **로그**: 대화 로그 user_id 스코프 저장, 품질 개선 목적 고지 (클릭스트림 동의와 한 세트)
- **호출 방식**: 동기 (design.md §7.1 "Kafka는 수집 파이프라인+fan-out 2곳만" 원칙 준수)

## 7.5 개인화 연동 — 계정 제외재료 양방향 (구 `chat-account-personalization-integration`)

챗봇 세션 개인화("돼지고기 빼줘")와 마이 페이지 영속 제외재료(`account.user_excluded_item`)를 **양방향 동기화**:
- **READ**: 마이 페이지 제외재료 → 챗봇 추천에서 자동 제외(설정이 대화에도 반영).
- **WRITE**: 챗봇 "빼줘" → 마이 페이지에 영속(대화가 설정에도 반영).

**구현(내 몫) 완료**: `services/chat/app/pipeline/account_client.py`가 account API(`GET/POST/DELETE /users/excluded-items`, JWT 스코프)를 호출(read `get_excluded_item_ids` / write `add_excluded_items`) — **남의 테이블 직접 안 건드리고 API만**. `main.py`가 비선호 등록 시 영속 호출 + 추천 시 세션 비선호와 **합산 적용**. 유저 `Authorization` 헤더를 그대로 account에 포워딩.

**활성 상태**: `ACCOUNT_INTEGRATION_ENABLED`(+`ACCOUNT_BASE_URL`) env로 토글, 기본 OFF면 `account_integration_enabled=False` → 무동작(세션 스코프만, graceful). 초기 유일 블로커였던 **JWT/Gateway 인증은 해소**(2026-07-19 계정연동 프로덕션 ON). 영속화는 수집 동의 트랙(`chat-conversation-data-plan.md §4`)에 게이팅.

**담당 경계**: AI(챗봇 측 연동·필터, API만) · 백엔드(`services/account` 제외재료 API, `get_current_user` 스코프) · 인프라(JWT·배포 설정) · 제품/데이터(영속화 동의).

## 8. 구현 계획 — 5일 (6h/일, MVP)

**전제**: NER `/ner` 엔드포인트 가동 · PG 재고/예산 + ES 레시피 + 가격 테이블에 실데이터 존재. (착수 시점 = 이 전제 충족 직후)

| 일차 | 작업 |
|---|---|
| 1 | Chat Service 뼈대 + Generator 인터페이스·팩토리 + 검색 1소스 e2e 관통 |
| 2 | 병렬 검색 4소스 + 품목코드 조인 컨텍스트 조립 |
| 3 | 질문 분석(NER 호출·규칙 의도분류·예산 파싱) + 무응답 처리 + 광역 폴백 |
| 4 | 가드레일(입력 필터·행동 화이트리스트) + 근거 태그 + 액션 버튼 페이로드 |
| 5 | PWA 채팅 UI + Redis 캐시·요청 상한 + 버퍼 |

제외(MVP 밖): C층 레시피 변형(+2일) · 멀티턴 세션(+1일, §5-②) · 의도분류 ML화 · Grafana 커스텀 패널. LLM 전환 시 GeminiGenerator/BedrockGenerator 구현 + 프롬프트 튜닝 +1일.
