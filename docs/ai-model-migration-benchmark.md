## 1. 측정 방법 (재현 가능하게 전부 명시)

### 1.1 무엇을 몇 번 측정했나

| 항목 | 값 |
|---|---|
| 모델 수 | **11개** (서울 4 · 도쿄 5 · 리전비교 1 · Google 1) |
| 모델당 케이스 | **50개** = 평문 챗 25 + 무말투 구조화 25 |
| 총 LLM 호출 | **550건** (에러 0건) |
| 추가 OCR 실측 | claude-3-haiku × 15장(실물 13 + 합성 2) |
| 사전 OCR 실측 | Nova Lite/Pro × 15장, Gemini 기준선(문서 T4) |
| 측정일 | 2026-07-28 |

### 1.2 트랙 A — 평문(사람 말투 반영)
- **입력**: 실제 서비스의 refine 프롬프트를 **코드에서 원문 추출**(`services/chat/app/pipeline/generator/gemini.py`의 `_SYSTEM`) + 동일 content 포맷 `[질문]\n…\n\n[근거]\n…`
- **파라미터**: `max_tokens=200`, `temperature=0.3` (실제 `config.py` 값과 동일)
- **케이스 25개**: 재료추천 15 + 예산추천 10. 근거는 실제 `TemplateGenerator._recommend()` 출력형식 그대로
- **채점**: 실제 프로덕션 가드레일 **`check_output_grounded()` 를 import 해서 그대로 사용** (출력의 모든 숫자·재료 item_id가 근거 안에 존재해야 통과) + 레시피 이름 보존율

### 1.3 트랙 B — 무말투(구조화 추출)
- **입력**: 영수증 텍스트 → JSON. 매장 10종 × 품목 카탈로그 24종에서 **결정적 생성(seed=7)**, 정답(truth) 동봉
- **파라미터**: `max_tokens=800`, `temperature=0.0`
- **채점**: 매장명 exact · **품목명+가격 쌍 정확도** · 합계 exact (정답 대조)

### 1.4 채점의 정직한 한계
- 챗 25케이스 중 **7개(`C01, C03, C05, C17, C21, C22, C23`)는 11모델 전원 실패** — 질문에 나온 재료·예산("대파","8천원")을 답변이 되풀이하면 가드레일이 '근거 밖'으로 판정하기 때문. **모델 변별력이 없는 구조적 케이스**라 리더보드는 나머지 **18개(변별 케이스)** 기준으로도 함께 제시했다.
- 프로덕션에서 이 판정은 **template 출력으로 안전 fallback** 되므로 사용자 피해는 없다(비용만 낭비).
- 구조화 트랙은 합성 텍스트라 **레이아웃 난이도가 없다** — 이미지 OCR 난이도와 동일시하면 안 됨(그래서 OCR은 실물 이미지로 별도 측정).

## 4.5 부수 발견 — 가드레일 오탐 (모델 이전과 독립된 개선건)

챗 실패 **109건**(11모델 합산)을 분해하면 대부분이 모델 결함이 아니다.

| 구분 | 건수 | 비율 | 성격 |
|---|---|---|---|
| **질문-되풀이 오탐** | **82건** | **75%** | 환각 아님 — 가드레일 결함 |
| 실제 결함(환각·이름누락) | 27건 | 25% | 진짜 모델 문제 |

**원인**: `check_output_grounded(answer, reference)`가 **template 출력만** 근거로 삼고 **유저 질문은 보지 않는다.**

- `C01` "두부랑 **대파**로 뭐 해먹지" → 답변 "두부와 **대파**로…" → 근거에 '대파'가 없어 **환각으로 오판**. 그러나 대파는 **유저가 말한 재료**다.
- `C17` "**8천원** 예산으로…" → 답변 "8천원…" → 근거엔 `8000`뿐이라 숫자 `8`이 위반으로 잡힘.

**프로덕션 영향**: 오판 시 refine 결과를 버리고 template으로 fallback → **유료 LLM 호출을 하고도 결과를 폐기**(비용 낭비 + 자연스러운 문장 손실). 해당 패턴("재료 말하며 추천 요청", "예산 말하며 추천 요청")은 **실사용 빈도가 높다**.

**수정안** — 근거에 질문을 합산(유저가 이미 말한 것의 되풀이는 환각이 아니다):

```python
# services/chat/app/pipeline/generator/gemini.py 호출부
check_output_grounded(polished, base.text + "\n" + question.raw_text, self._ingredient_index)
```

추가로 한글 수사 정규화("8천원"→8000)를 넣으면 숫자 오탐도 해소된다.

> ⚠️ **이 수정은 모델 순위·이전 결론을 바꾸지 않는다** — 전 모델(현행 Gemini 포함) 점수가 함께 오르기 때문. 리더보드의 "변별 18케이스"는 이미 이 오탐을 제외한 값이다.

### 5.1 채점 기준 명확화 — 무엇을 "성공"으로 세었나

- **파싱 15/15** = JSON 형식이 깨지지 않았는지 **형식만** 판정. 내용 정확도와 무관.
- **합계정합 2/15** = Σ품목가격 == total. **13/15 실패**.
- **품목명·매장명 정확도는 채점하지 않았다** — 실물 13장은 정답(ground truth)이 없기 때문. 아래 출력은 **채점값이 아니라 모델 원출력**이다.

## 5.5 결과 ⑤ 분류·감정분석 (신규 기능 적합성)

**목적**: 챗·OCR 이전이 막힌 상황에서 **Bedrock이 잘하는 태스크 유형**을 실측으로 찾는다.

**측정**: 품목분류 25건(카테고리·보관법·식비포함, 정답=`classify.py` 정책) + 리뷰 감정분석 25건(긍정/부정/중립) × 4모델 = 200건.

| 모델 | 카테고리 | 식비포함 | 보관법 | 분류 전체 | **감정분석** | 감정 지연 |
|---|---|---|---|---|---|---|
| `gemini-flash-lite` | 25/25 | 25/25 | 25/25 | 25/25 | **25/25** | 785ms |
| `nova-micro-seoul` | 22/25 | 25/25 | 20/25 | 18/25 | **24/25** | 351ms |
| `nova-lite-seoul` | 21/25 | 22/25 | 22/25 | 18/25 | **23/25** | 360ms |
| `claude-3-haiku-seoul` | 24/25 | 21/25 | 23/25 | 19/25 | **24/25** | 446ms |

**판정**
- ✅ **감정분석 = 이전 적합**: nova-micro **24/25** vs Gemini 25/25 — 실질 동급이며 **351ms(2.2배 빠름)·0.0095원(약 절반)**. 유일 오답은 "레시피 잘 봤습니다"(중립→긍정) 경계 케이스.
- ❌ **OCR 티어7 품목분류 = 부적합**: nova-micro 18/25(카테고리 22·**보관법 20**) vs Gemini 25/25. 실패는 보관법(햇감자 ROOM→FRIDGE)과 가공식품 경계(냉동만두·바나나킥·참치액을 식재료로 오분류).

### 5.5.1 측정 중 발견한 프롬프트 함정 (공정성 보정)
최초 프롬프트는 스키마를 `"category": "식재료|가공식품|비식품|조정"` 형태로 줬는데, **nova-micro가 이 파이프 문자열을 값으로 그대로 복사**해 3/25로 폭락했다(모델 무능이 아니라 지시따르기 실패).

```
입력: 국내산 삼겹살 500g
출력: {"category": "식재료|가공식품|비식품|조정", ...}   ← 열거형 표기를 값으로 복사
```

→ **명시적 열거**("반드시 다음 넷 중 하나를 골라 쓴다: 식재료 / 가공식품 / 비식품 / 조정" + 예시 출력)로 바꿔 **전 모델 재측정**했고, 위 표는 그 결과다. Gemini는 두 프롬프트 모두 25/25로 무영향 — **작은 모델일수록 스키마 표기법에 민감**하다는 실무 교훈.

**케이스.** 실 리뷰 데이터(만개 후기 141,298건)에서 후기 8~200건인 레시피 **8개**를 무작위 추출,

**채점.** 자유 요약은 정답이 없으므로 **지시 준수**를 기계 판정했다.
  · 문장 수(2~3 요구) · **존댓말 종결**(정규식 `(습니다|입니다|해요|…)$`) · 길이 · 지연

|---|---|---|---|---|---|

```

                    좋다는 점이 자주 언급된다. 다만 물의 양이 명확하지 않아 간이 제대로 되지
                    않는다는 지적이 있으므로 정확한 용량 표기가 필요하다.
                    → "~언급된다"·"~필요하다" 평서체(존댓말 아님). 내용은 정확하나 지시 위반.

[claude-3-haiku]    이 요리 레시피에 대한 후기들을 종합해보면, 대체로 맛있고 간단한 요리라는
                    긍정적인 평가가 많습니다. 다만 물 양 조절이 중요하고 … 있습니다.
                    전반적으로 만족스러운 반응이지만, 개인의 취향에 따라 약간의 조정이
                    필요할 수 있습니다.
                    → 존댓말 준수. 다만 군더더기 서두와 3문장 초과.
```

### 이 측정에서 얻은 규칙

1. 🔴 **신형이 항상 낫지 않다.** `haiku-4.5`(존댓말 0/8) < `haiku-3`(8/8). 같은 계열에서 세대가
   올라가며 지시 준수가 **나빠졌다**. 모델 선택 근거는 세대가 아니라 **태스크별 실측**이다.
2. 🔴 **태스크 간 전용 금지.** `nova-micro` 는 챗 refine(§5.2 실험 G)에서 Gemini와 **동률**이었으나
   자유 요약에서는 지시를 어긴다. 두 태스크 모두 "한국어 문장 생성"으로 묶이지만 성격이 다르다 —
   refine 은 **주어진 근거의 재작성**, 요약은 **다수 입력의 압축·논조 판단**이다.
3. ⚠️ **미포함어율은 변별력이 없었다.** 요약에 등장한 한글 2글자+ 중 원문에 없는 비율이 5종 모두
   70~76%로 갈리지 않았다. 한국어 활용형 때문에 문자열이 어긋나는 조악한 지표다 —
   창작 여부는 `--audit` 으로 **사람이 원문과 대조**해야 한다(자유 서술은 가드레일 기계검증 불가).
