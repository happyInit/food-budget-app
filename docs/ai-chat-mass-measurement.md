| 인프라(스로틀) | 4 | ⚪ 무관 | 벤치 병렬 12로 인한 `ThrottlingException` — 모델 결함 아님 |

### 2.1 가장 심각했던 것 — 다품목에서 이름을 잘라먹음

근거에 요리가 여러 개일수록 심했다. 실제 분포:

```
3개 중 0개만 언급  13건
4개 중 1개만 언급  12건
3개 중 1개만 언급  12건
6개 중 1개만 언급  11건
```

### 2.2 버그성 동작 — 질문 텍스트를 요리 이름으로 인용

```
Q: 연근랑계란로뭐해먹지          (공백 없는 입력)
근거: '새우튀김', '닭볶음탕' 같은 요리는 어때요?
출력: '연근랑계란' 같은 요리는 어때요?   ← 질문을 요리명처럼 인용
```

작은따옴표를 **근거의 요리 이름이 아닌 질문 텍스트에 붙이는** 동작이 11건 나왔다. 사용자에게는 존재하지 않는 요리를 추천하는 것처럼 보인다.

### 2.3 채점기 자체의 오탐도 발견

초기 채점은 `num_drop` 91건을 보고했으나, 분해해보니 **대부분이 실제 손실이 아니었다**:
- `(재료 5개 …)`의 **개수 표기**가 빠진 것 → 금액은 100% 보존
- 근거 `20000` → 출력 `2만원` **표기 변환** → 정보 동일

→ **금액 손실**과 **메타 손실**을 분리하는 채점기로 고쳐 재집계했다. 이 분리가 없었으면 재료비 카테고리를 과잉 진단할 뻔했다.

## 5. 정직한 한계 · 남은 문제

- **스로틀 증가**: 튜닝본에서 `ThrottlingException`이 4→27건으로 늘었다. 프롬프트가 길어져(입력 997→1,676토큰) 처리량이 늘고 **벤치의 병렬 12**가 계정 한도를 건드린 것으로, **모델 품질 문제가 아니다**. 실서비스는 동시성이 훨씬 낮아 재현되지 않을 가능성이 크나, **부하 시 재확인이 필요**하다.
- **지연 증가**: p50 718ms → 1881ms. 위 스로틀 재시도가 섞인 값이라 순수 모델 지연으로 보면 안 된다. **동시성 낮춰 재측정 필요**.
- **입력 토큰 증가**: 997 → 1,676 (+68%). 단가가 오르지만 nova-micro 입력 요율($0.035/1M)이라 호출당 증가분은 0.01원 미만.
- **재료비 카테고리는 여전히 약함**(금액 손실 30건). 다만 이 경로는 프로덕션에서 **refine을 타지 않는다**(`gemini_refine_recommend_only=True`) → 실사용 영향 없음. 향후 refine 대상을 넓힐 때 재검증 필요.
- **거절 경로**는 근거가 비어 프로덕션에서 **LLM 호출 자체가 없다**(`if not base.basis: return base`). 계측엔 포함했으나 실사용과 무관하다.
- 합성 근거를 사용했다. 실제 검색 결과의 문장 다양성은 이보다 넓을 수 있다.
