## 0. 맥락

OCR은 **F5 냉장고 재고 등록**·**F17 식비 기록**의 공통 입구다(`service-spec-handoff.md`). 출력은 어느 방식이든 동일하게 **재료 NER → item_master 표준품목코드**로 넘어가므로 **뒷단 파이프라인은 방식 무관**(`ai-spec.md §7`). 따라서 방식 선택은 **입구(이미지→구조화 품목)** 구간에 국한된다.

도메인 난이도: 대상이 **한국어 감열지(thermal) 영수증** — 저대비·퇴색·구겨짐이 흔한 OCR 최악 구간.

## 1. 선택 기준 8가지

| # | 기준 | 이 프로젝트에서 중요한 이유 |
|---|---|---|
| 1 | 정확도(한국어 감열지) | 도메인이 감열지 — 여기 성능이 실사용을 좌우 |
| 2 | 구현 공수/난이도 | 8~9주 캡스톤·소팀. 영수증 OCR = 탐지+인식+**레이아웃 파싱**까지라 공수 편차 큼 |
| 3 | 런타임 비용 | 장당 과금·반복성. **무료 API 절대제약**(`AGENTS.md`)과 직결 |
| 4 | 오프라인/API 의존 | 가용성·지연·오프라인 가능 여부 |
| 5 | 유료예외 승인 | 유료 API는 팀 재승인 필요(`AGENTS.md`) — 절차 비용 |
| 6 | 학습데이터 요구량 | 실물 영수증 20장도 겨우 확보 — 데이터 기아. 학습 필요 방식엔 치명적 |
| 7 | 구조/레이아웃 출력 | 영수증은 2D 표. raw text만이면 파서 별도, 구조 JSON이면 파서 불필요 |
| 8 | 프라이버시 / moat | 영수증=개인 구매정보(외부전송?) + 자체모델 moat 철학 부합도 |

## 3. 방식별 장단점

### ① Tesseract 단독
- 👍 무료·오프라인·프라이버시·승인 불필요. 깨끗한 인쇄 영수증엔 충분.
- 👎 한국어 감열지 약함(그림자/구겨짐 급락). raw text만 줘서 **좌표 파서 1.5~2주 직접**.

### ② Gemini Vision 단독 — ⭐ 유력
- 👍 감열지·한국어 정확도 최강. **공수 최소**(탐지·인식·레이아웃을 모델이 한 번에 + 구조 JSON 직출력). zero-shot(데이터 불필요).
- 👎 장당 <1원 **반복 비용** + **API 의존**(오프라인 불가) + **유료예외 승인 필요** + 영수증 **외부 전송**(프라이버시) + moat 축소.

### ③ CNN+RNN+LSTM (CRNN) — 비추천
- 👍 자체모델(포트폴리오)·로컬·프라이버시.
- 👎 **데이터 기아가 치명**(수만 라벨 필요, 20장뿐) + **인식만**이라 검출기·레이아웃 별도 대공사 + **수주~수개월** + 사전학습/VLM 못 이김. **moat는 NER이 이미 담당** → OCR엔 쓸 자리 아님.

### ④ Tesseract + Vision 폴백
- 👍 비용 최소(쉬운 건 무료)·정확도 확보.
- 👎 **공수 최대**(파서 + 실패판정 + Vision경로 전부).

### (기각) CLOVA OCR (네이버)
- 영수증 Document 모델이 유료 → **무료 API 절대제약 충돌로 기각**(`data-validation.md §132`).

## 4. 결론

결정적 기준 = **공수(2)·감열지 정확도(1)·데이터기아(6)**.
- **CRNN 탈락**(6·2 치명), **④ 폴백 단독 채택 보류**(2 공수 최대).
- **Vision vs Tesseract** = "정확도·공수(Vision)" vs "비용·오프라인·승인(Tesseract)" 트레이드오프. 도메인이 감열지라 **Vision 우세**.
- 뒤에 **HITL 확정**이 있어 정확도 미달분은 사람이 보정 → Vision의 높은 정확도가 HITL 부담을 더 줄임.

**→ 채택 방향: 방식무관 백엔드 골격 + 1순위 구현체 = Vision, 폴백 = Tesseract, CRNN 제외.**
최종 확정은 **실물 영수증 20장 PoC**로(`ai-spec.md §7`). 골격 상세는 [`ocr-service-design.md`](ocr-service-design.md).

### 결정 근거 (요약)
- **Gemini Vision 단독** — 결정적 기준(감열지 정확도·구현 공수·구조화 출력, §비교·§5 실측)에서 우위. 단순성·정확도가 비용 증가를 상회.
- Tesseract 폴백·CRNN 보류. 골격의 **교체가능 인터페이스는 유지**(향후 폴백/오프라인 대비 무비용 보험).
- ⚠️ 유료 API → **팀 승인·유료예외 문서화 대상**(AGENTS.md).
- PoC는 방식 선택이 아니라 **정확도 실측·프롬프트 튜닝용**.

## 5. 실측 비교 (자체 측정, 2026-07-16) — Tesseract vs Gemini Vision

공개 벤치마크가 아니라 **우리 이미지로 직접 잰 데이터**(팀 요구). ⚠️ **합성 영수증**(Noto Sans KR 렌더)이라 실물 감열지 100% 대체는 아니나, **동일 조건 직접 비교**라 방향성은 신뢰 가능(실물 확보 시 갱신).

**테스트 이미지 2종** (레포 첨부 — 재현·검증용):
- 깨끗: [`assets/ocr/receipt_synth_clean.jpg`](assets/ocr/receipt_synth_clean.jpg) — GS25 5품목
- 저품질(감열지 근사): [`assets/ocr/receipt_synth_degraded.jpg`](assets/ocr/receipt_synth_degraded.jpg) — 저대비+블러+노이즈+미세회전

### 5.1 정확도·지연 (정답 12필드 = 매장·일시·품목4×[이름·가격]·합계)

| 이미지 | Tesseract(kor) | Gemini Vision (thinking OFF) |
|---|---|---|
| 깨끗 | **10/12** · 0.2s · ⚠️ raw text(구조 없음, GS25→"6525" 등 오탐) | **11/12** · **2.5s** · ✅ 구조화 4품목 |
| **저품질** | **0/12** · 0.1s · ❌ **빈 출력(완전 실패)** | **11/12** · **2.1s** · ✅ 구조화 4품목 |

→ **깨끗은 근소(10 vs 11)하나, 저품질에서 Tesseract 붕괴(0/12) vs Vision 유지(11/12).** 우리 도메인=감열지라 이 격차가 결정적. 게다가 Tesseract는 **raw text만**이라 품목·가격 구조화엔 **별도 파서(1.5~2주) 필요**, Vision은 1호출로 JSON 직출력.

### 5.2 비용·지연 (실측 토큰 · 유료 티어)
모델 `gemini-flash-latest` = 실제 **`gemini-3.5-flash`**(thinking 모델). OCR은 추론 불필요라 **`thinking_budget=0`(OFF)** 채택 — 비용·지연 대폭↓, 정확도 동일(실측 확인):

| 설정 | 실측 토큰(합성 5품목) | 지연 | 비용(flash 0.30/2.50) |
|---|---|---|---|
| thinking 기본 | in 1,311 · out 334 · **thoughts 828** | 24~41s | **4.55원/장** |
| **thinking OFF (채택)** | in 1,311 · out 334 · thoughts 0 | **~2.5s** | **1.70원/장** |

- ⚠️ **thinking 토큰(828, 출력요율 과금)이 비용·지연의 주범**이었음 — 끄면 **비용 63%↓·지연 16배↓**.
- 실물 ~17품목은 출력 토큰↑ → 대략 2.5~3원/장 추정(그래도 flash-lite 요율이면 <1원).
- ⚠️ **키는 무료 티어였음**(하루 20건) → **유료 전환 완료**(2026-07-16). `gemini-3.5-flash` 실요율은 공식 페이지 재확인 권장.
- Tesseract: **0원**(로컬)이나 저품질 정확도 0·구조화 부재로 **실사용 불가**.

### 5.3 결론
저품질(감열지) 정확도 + 구조화 원샷에서 Vision이 Tesseract 대비 **압도적**(0/12 vs 11/12). **thinking OFF로 2.5초·1.70원/장** — 지연·비용 우려도 해소. 방식 선택 근거로 충분.
