# 최종 발표 플로우 (20분 · 4인 · 시연 영상 삽입)

> 전제 = **A3 컷오버 뒤 발표**(AWS 운영 중). 발표자 4인(태현 제외).
> 기존 `docs/mp_k8s_presentation_bongsu.md`(봉수 0~8)는 **K8s 시점** 문서다 —
> 이 문서가 그것을 3막(Docker→K8s→AWS)으로 재편한 **최종본 뼈대**이고, 세부 대본은 그쪽을 재사용한다.

## 0. 관통선 — 이 한 줄이 발표 전체를 잡는다

> ## **"우리는 이 앱을 세 번 이사시켰습니다. 마지막 이사의 다운타임은 5~10분이었습니다."**

**왜 이게 클라우드 과정에 맞는 관통선인가.**
대부분의 팀은 *"AWS 로 만들었습니다"* 를 보여준다. 그건 **한 번도 안 옮겨봤다**는 뜻이기도 하다.
클라우드 역량의 본질은 특정 인프라에 종속되지 않는 설계이고, 그건 **실제로 옮겨봐야만 증명된다.**

```
Docker Compose (단일 호스트)  →  K8s 온프렘 (kubeadm 5노드)  →  AWS EKS
        ①                               ②                          ③
   한계를 몸으로 겪음              이식성을 "설계"함            그 설계가 통했는지 "검증"
```

🔴 **핵심 증거 = 온프렘을 한 줄도 안 건드리고 AWS 로 갔다.**
`overlays/onprem` 렌더 **38 트랙 sha256 동일**. 이관은 기존 것을 고치는 게 아니라 **덧셈**이었다(C-72·C-83).
⇒ *"옮길 수 있게 만들었다"* 가 말이 아니라 **diff 로 증명된다.**

### [0] 오프닝 (봉수 · 1분)

한 장. 세 개의 박스와 화살표 두 개. **말은 세 문장.**

1. "월 식비 예산 안에서 뭘 먹을지 정해주는 앱을 만들었습니다."

🔴 **여기서 아키텍처 다이어그램을 띄우지 말 것.** 도입에서 복잡한 그림을 보여주면 청중이 그걸 읽느라

### [1] 서비스 (건우 · 4분) — 🎬 영상 ①

**메시지: 문제가 구체적이고, 데이터가 진짜다.**

**① 문제 (40초)**
- 월 식비 예산은 정해져 있는데, "이번 주에 뭘 사서 뭘 해먹지"는 매번 처음부터 계산해야 한다
- 레시피는 재료를 알려주지만 **가격은 안 알려준다**

**② 해결 흐름 (1분) — 한 장으로**
```
레시피 → 재료 추출 → 마켓컬리·오아시스 현재가 조회 → 예산 내 식단 계획 → 장바구니 → 지출 추적
```
🟢 여기서 **AI 가 어디에 끼는지**를 화살표로 표시해두면 [2]로 자연스럽게 넘어간다.

**③ 🎬 영상 ① — 실사용 (40초)**
로그인(카카오) → 예산 설정 → 추천 → 장바구니 담기 → 지출 반영.
🔴 **실서비스 화면이다** — `app.mealbong.cloud` 라이브(실측 HTTP 200 · 0.44s).

**④ 왜 13종으로 쪼갰나 (1분 20초)**
- `account` `recipe` `mealplan` `price` `pantry` `recipebook` `notify` `chat` `ocr` `video`
  `ranking-serving` `operations` `frontend` = **13종**
- 🔴 **"마이크로서비스가 멋있어서"가 아니라고 말해야 한다.** 실제 근거 두 개:
  - **스케일 단위가 다르다** — 부하테스트에서 `recipe` 만 병목이었다(→ [3]에서 숫자로 회수)
  - **크로스-서비스는 DB 조인이 아니라 API 호출**로 묶어 스키마 결합을 끊었다(스키마-퍼-서비스)
- 🟡 정직: 5인 팀에 13종은 **많은 편**이다. 물으면 *"팀원별 소유 경계를 만들려고 나눴고,
  운영 부담은 GitOps 로 흡수했다"* 로 답한다(→ [3]·[4] 콜백).

### [2] 데이터·AI (정은 · 3분)

**메시지: 데이터가 공개 API 가 아니라 우리가 직접 만든 파이프라인에서 나온다.**

**① 수집 (1분)**
- 마켓컬리·오아시스마켓 **신선+가공 크롤**(교육용 비상업) · 만개의레시피 레시피 DB
- CronJob 7종 + Kafka 3브로커. 🟢 **온프렘이 이걸 상시 프로덕션으로 계속 돈다**(C-3 이중역할 — [4] 복선)
- 실측 규모를 하나만: 크롤 적재가 만드는 **WAL 213 MiB/h**

**② AI — 🔴 돌아가는 것과 준비 중인 것을 나눠 말한다**

| | 상태 | 팩트 |
|---|---|---|
| 재료 NER (CRF) | ✅ 학습·사용 중 | gold **F1 0.924** — ⚠️ **레시피 재료목록 분포 한정** |
| 최저가 이상탐지 | ✅ 동작 | 통계 기반(z-score·성숙도 게이트) · 알림 fan-out |
| 영수증 OCR | ✅ 라이브 | Gemini · 냉장고 재고 + 식비 반영 |
| YouTube 추출 | ✅ 라이브 | URL → Gemini 멀티모달 → CRF NER |
| 개인화 랭킹 | 🟡 **설계·배선 완료, 학습 대기** | 라벨 수집 배선이 이번 주 완료(#637·#639) |
| 챗봇 LLM | 🟡 **백엔드 준비, 미활성** | 현재 template · Bedrock 배선 대기 |

🔴 **과장 금지.** *"AI 로 개인화 추천합니다"* 라고 말하면 안 된다 — 지금은 **규칙 기반 랭킹**이고
ML 재랭킹은 폴백 상태다. 대신 이렇게 말하면 **더 강하다**:
> "학습 라벨이 0인 걸 발견하고, 노출↔행동 조인이 왜 실패했는지 추적해서 이번 주에 고쳤습니다.
>  모델보다 **데이터 파이프라인이 먼저**라는 걸 배웠습니다."

**③ 전 과정 CPU (30초)**
GPU 없이(GTX 1060 3GB) CRF·XGBoost·LightGBM 으로 설계 — **제약을 먼저 정하고 모델을 골랐다.**

### [3] 운영 (정현 · 5분) — 🎬 영상 ②

**메시지: 우리는 "돌아간다"가 아니라 "재현 가능하게 돌아간다"를 만들었다.**

**① 배포전략 — 🎬 영상 ② 카나리 (1분 30초)**
- Argo Rollouts. `recipe` **0 → 20% → 50% → 100% 자동 promote 실증**
- 촬영 가이드가 이미 있다: `docs/mp_k8s_canary_demo.md`(4컷 · 무트래픽도 통과하도록 하드닝됨)
- 🟡 정직: **전 서비스가 아니라 `account`·`recipe` 2종만** 카나리다(ADR-0001).
  나머지는 롤링 — *"트래픽이 실제로 갈리는 진입 경로에만 걸었다"*

**② 부하테스트 → HPA 도출 (2분) ⭐ 이 발표에서 두 번째로 강한 카드**
- 🔴 **HPA 값을 감으로 정하지 않았다.** k6 로 포화 스윕 → knee 를 target, peak 를 max 로
- 실측: `recipe` **1 → 4 replica** 에서 **p95 2.7s → 46ms**
- 🟢 **그리고 병목이 `account` 로그인으로 이동했다** — *"스케일아웃은 병목을 없애는 게 아니라 옮긴다"*
- 🟢 **HPA 가 안 통하는 병목**도 분류했다 — `mealplan`·`chat` 은 다운스트림 대기라 replica 를 늘려도 안 준다
- CNPG Pooler: `account` **4 replica 에서도 PG 커넥션 12/100**

**③ 관측 (1분)**
- kube-prometheus-stack + **LGTM**(Loki·Tempo·Alloy) · 스크레이프 **73 타깃**
- 내부 도구 6종을 `https://<이름>.mealbong.cloud` 로 정리(NodePort 회수)

**④ 보안 — defense-in-depth (30초, 표 한 장)**
| 축 | 실측 |
|---|---|
| 네트워크 | app ns **양방향 default-deny** · 차단 실증(world→15021 DROPPED / 443 200) |
| 사람 | RBAC Phase1 · `auth can-i` **20/20** |
| 파드 | PSA **10 ns** 적용 |
| 저장 | etcd at-rest 암호화 · **137/137 암호문**(평문 0) |
| 전송 | Istio mTLS · cert-manager 자동 갱신 |

### [4] AWS 이관 (봉수 · 5분 30초) — 🎬 영상 ③ **클라이맥스**

**메시지: 설계가 통했다. 그 증거는 diff 와 다운타임이다.**

**① 왜 온프렘을 먼저 거쳤나 (50초)**
- 처음부터 AWS 로 갈 수도 있었다. 안 간 이유 = **비용을 내면서 배우는 대신, 배우고 나서 비용을 낸다**
- 온프렘 = **리허설**. 여기서 겪은 것: 호스트 **급사 3회** → 그게 배치 원칙이 됐다
  (master·quorum 다수·Prometheus 는 B / PG·Redis primary 는 A)
- 🟢 *"장애를 겪고 설계를 바꿨다"* 는 클라우드 과정에서 가장 설득력 있는 문장이다

**② 이식성을 어떻게 설계했나 (1분 20초) — ⭐ 발표의 심장**
- **kustomize base + overlays/{onprem, eks}**. base 는 두 사이트가 공유, 갈리는 것만 overlay
- 라이브 코드 워크스루 한 장(`account` kustomization) — 기존 봉수 노트 §0 대본 재사용
- 🔴 **원칙: 온프렘 동결 · 덧셈만**(C-72·C-83). 이관은 기존 경로를 고치는 게 아니라 **새 경로를 붙이는 것**
  - 예: `EVENT_SINK` 기본값을 현행(`kafka`)으로 둬서 **온프렘 ConfigMap 을 안 건드리고** EKS 만 `pg`
- **증거: `overlays/onprem` 렌더 38 트랙 sha256 동일** ← 이 한 줄이 이 블록 전체를 지탱한다

**③ 어떻게 옮겼나 — A0~A6 (1분)**
```
A0  기반    VPC·EKS·노드그룹·CNI·CSI·Istio·ArgoCD·관측   (트래픽 0 · 데이터 0)
A0.5 CI     GitLab(EC2) → ECR arm64                      ← A1 이 이걸 요구한다
A1  데이터   CNPG 빈 클러스터 · ECK · ElastiCache
A2  앱      12종 + aws.mealbong.cloud 내부 검증
A3  컷오버   쓰기 중단 → pg_dump 318MiB → restore → ES 재파생 → DNS   ⭐ 다운타임 5~10분
A4~A6 안정화 · 파이프라인 · 온프렘 축소
```
🔴 **A3 를 한 창에 몰아넣은 이유**를 꼭 말할 것 — K8s 이전 때는 앱/데이터를 나눠 옮겼지만(P1/P2),
AWS 는 **사이트 간 상시 연결이 없어서**(C-41) 그 중간 상태가 **존재할 수 없다.**
*"같은 순서를 그대로 쓰면 안 되는 이유를 찾은 것"* 이 설계 역량이다.

**④ 🎬 영상 ③ — 컷오버 (60초) ⭐⭐⭐**
DNS 전환 순간 + 스모크 통과 + 첫 요청이 AWS 로 들어오는 화면.
**이 영상이 이 발표의 유일무이한 자료다** (→ §4 촬영 계획)

**⑤ 아키텍처가 어떻게 바뀌었나 (1분) — before/after 한 장, 바뀐 박스에만 화살표**
| | 온프렘 | AWS |
|---|---|---|
| 진입 | MetalLB L2 | **ALB**(ACM·WAF) |
| 오브젝트 | MinIO | **S3** |
| Redis | Sentinel 5파드 | **ElastiCache Valkey** |
| 스토리지 | OpenEBS LVM | **EBS gp3** (PVC **352 → 125 GiB**) |
| 노드 | kubeadm 5대 amd64 | **EKS · m7g Graviton × 3 + Karpenter** |
| PG·ES·Kafka | CNPG·ECK·Strimzi | 🟢 **그대로 자체운영** |

🔴 **마지막 줄이 제일 중요하다.** RDS·OpenSearch·MSK 를 **일부러 안 썼다** — 비용(C-15·C-10) +
매니지드로 갈아타면 이식성 증명이 성립하지 않는다. 물으면 이렇게 답한다:
> "매니지드를 쓰면 편하지만, 그건 AWS 에 종속되는 선택입니다.
>  우리는 **옮길 수 있는가**를 증명하는 게 목표라 오퍼레이터를 그대로 가져갔습니다."

**⑥ 비용 (30초)**
실단가 산정 **$857 → 목표 $219**. 수단 = Graviton · Karpenter 평시 0대 · PVC 64% 감축.
🟡 **Spot 은 일부러 안 썼다** — 실측 CPU 요청/실사용 **9.4배** vs 메모리 **1.1배**.
*"우리가 사는 건 CPU 가 아니라 메모리라 Spot 할인이 10%에만 걸린다"*

## 3. 🔴 정직 안전판 — 말하면 안 되는 것

발표에서 **사실이 아닌데 말하기 쉬운 것들**이다. 멘토가 정확히 여기를 판다.

| ❌ 말하면 안 되는 것 | ✅ 사실 |
|---|---|
| "AI 로 개인화 추천합니다" | 현재 **규칙 기반**. ML 재랭킹은 모델 미적재로 폴백 중(이슈 #649) |
| "챗봇이 LLM 으로 답합니다" | 현재 `template`. Bedrock 은 **배선 대기**(이슈 #651) |
| "전 서비스 Blue-Green" | **이관 후 계획**(C-27). 지금은 카나리 2종 + 롤링 |
| "멀티 아키텍처로 빌드합니다" | **사이트별 단일 아키**(C-89) — arm64(AWS) / amd64(온프렘). 멀티아치는 **의도적 미채택** |
| "무중단 이관" | **5~10분 다운타임**. 사이트 간 상시 연결이 없어(C-41) 무중단이 불가능한 구조였다 |
| "CRF 가 대화문장을 이해합니다" | **레시피 재료목록 분포**로만 학습. 대화체는 과다추출 — 그래서 챗봇에 **안 쓴다** |
| "완전 자동 배포" | ArgoCD auto-sync **30 / manual 16**. 데이터 CR·정책은 **일부러** 수동 |

🟢 **이걸 먼저 말하면 오히려 점수가 올라간다.** *"여기까지 됐고 여기부터는 안 됐습니다"* 를
구분해 말하는 팀이 드물다. 특히 마지막 줄(auto-sync 를 일부러 안 켠 이유)은 **성숙도의 증거**다.

### 🔴 A3 컷오버 촬영 — 지금 준비할 것

컷오버는 **되돌릴 수 없고 한 번뿐**이다. 그날 당황해서 녹화를 놓치면 발표의 클라이맥스가 사라진다.

- [ ] 화면 녹화 **미리 세팅**(터미널 폰트 키우기 — 발표 화면에서 읽혀야 한다)
- [ ] 창 배치를 미리 정한다 — 최소 3개
  - 창A: **연속성 관측** `while true; do date +%T; curl -s -o /dev/null -w "%{http_code}\n" https://app.mealbong.cloud/; sleep 1; done`
  - 창B: **전환 실행** (pg_dump → restore → DNS)
  - 창C: **AWS 쪽 수신 확인** (파드 로그 / 접속 카운트)
- [ ] 🟢 **다운타임 구간이 화면에 보이게** — 창A 의 200 → 실패 → 200 복귀가 **가장 설득력 있는 1컷**이다.
      숨기지 말고 **그대로 보여준다**(정직 + 실제 다운타임이 짧다는 증명)
- [ ] 시각을 화면에 남긴다(`date +%T`) — "5~10분"을 **말이 아니라 타임스탬프로** 증명

⚠️ 컷오버는 리스크 작업이다. **녹화가 작업을 방해하지 않게** 역할을 나눈다 — 실행자와 녹화자는 다른 사람.

## 5. 예상 질문 (멘토 대비)

| 질문 | 답의 뼈대 |
|---|---|
| "EKS 인데 왜 PG·ES·Kafka 를 자체운영?" | 비용(C-15·C-10) + **이식성 증명이 목적**이라 매니지드로 갈아타면 성립 안 함 |
| "Spot 왜 안 씀?" | 실측 CPU 요청/실사용 9.4배 vs 메모리 1.1배 — **우리가 사는 건 메모리**라 할인이 10%에만 걸림 |
| "무중단으로 못 했나?" | C-41 사이트 간 상시 연결 없음 → 중간 상태가 존재 불가. **5~10분을 설계로 선택** |
| "온프렘 왜 안 끄나?" | C-3 **이중역할** — DR 대기 + **크롤 상시 프로덕션**. 끄면 데이터 수집이 멈춘다 |
| "13종은 과하지 않나?" | 스케일 단위가 실제로 달랐다(부하테스트 근거) + 소유 경계. 운영부담은 GitOps 로 흡수 |
| "정량적 근거는?" (멘토 기지적) | 부하테스트 4분류 · WAL 213MiB/h · PVC 352→125GiB · 비용 $857→$219 · 커넥션 12/100 |
| "장애 겪은 적 있나?" ⭐ | **있다** — 급사 3회(→배치 원칙) · PGSync 슬롯 무효화(→WAL 실측) · 컬리 크롤 유실(→원인 `ERR_NETWORK_CHANGED` 확정) |

🟢 **마지막 줄이 숨은 강점이다.** 장애를 숨기는 팀이 대부분인데, **원인까지 확정한 사후분석**이
셋이나 있다. 시간이 남으면 하나를 30초로 넣으면 좋다 — 컬리 크롤 건은 *"907건이 범인인 줄 알았는데
첫 내비게이션이 범인이었다"* 라는 반전이 있어 이야기로도 좋다.
