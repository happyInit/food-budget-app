5. 정직한 한계 · 남은 문제

  • 스로틀 증가: 튜닝본에서 ThrottlingException이 4→27건. 프롬프트가 길어져(입력 997→1,676토큰) 벤치의 병렬 12가 계정 한도를 건드린 것으로 모델 품질 문제가 아니다. 실서비스는 동시성이 훨씬 낮으나 부하 시 재확인 필요.
  • 지연 증가: p50 718ms → 1881ms. 위 스로틀 재시도가 섞인 값이라 순수 모델 지연이 아니다 — 동시성 낮춰 재측정 필요.
  • 재료비 카테고리는 여전히 약함(금액 손실 30건). 다만 이 경로는 프로덕션에서 refine을 타지 않는다(gemini_refine_recommend_only=True) → 실사용 영향 없음. refine 대상을 넓힐 때 재검증 필요.
  • 거절 경로는 근거가 비어 프로덕션에서 LLM 호출 자체가 없다(if not base.basis: return base). 계측엔 포함했으나 실사용과 무관.
  • 합성 근거를 사용했다. 실제 검색 결과의 문장 다양성은 이보다 넓을 수 있다.
