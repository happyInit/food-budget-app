> **팀 논의 입력용 조사.** 작성 2026-07-12 · 방향 전환("식비+낭비→역량향상") 검증용.

## 1. 한 줄 결론
**우리 방향은 검증된 주류 패턴이다.** 핵심 난제("제품별 실제 소비기한 데이터는 어디에도 없다")는 성숙한 오픈소스(Grocy·Home Assistant)에서도 **동일하게 확인**됐고, 모두가 쓰는 우회책이 **"카테고리 참고값 추정 + 유저 입력 다양화(영수증 OCR 등)"** — 정확히 우리가 계획한 식약처 참고값 + 영수증 OCR 방식이다. 출시되는 낭비감소 기능도 **임박 알림 + 냉장고/임박 재료 기반 레시피 추천** 두 가지로 수렴한다.

## 3. 검증된 발견 (요지 + 출처)

**F1. 제품별 실제 소비기한 = 어떤 외부 소스에도 없다, 전부 유저 입력** (high)
Grocy·Home Assistant 트래커 README 명시: *"만료일은 바코드 DB에서 안 옴 → 오직 유저 수동입력."* Open Food Facts(300만+ 제품)는 **제품명·카테고리만, 만료일 없음.** → **우리 핵심 난제 그대로 확인.**
출처: github.com/grocy/grocy, github.com/wizz666/homeassistant-grocery-tracker

**F2. 지배적 우회책 = 카테고리 참고값 추정, 그리고 바로 쓸 공개 데이터셋 2개 존재** (high) ⭐
- 2018 해커톤(Snowflake)=Univ.Kentucky 만료 데이터셋 교차참조 / 냉장고파먹기=일반 소비기한 자동채움
- **① 식약처/KFIA "식품유형별 소비기한 참고값" DB — 2,037개 카테고리×조건 엔트리** (kfia.or.kr/kfia/sub.php?menukey=1513, 2022~2025 발표)
- **② USDA FoodKeeper — 400+ 품목, CC0 퍼블릭도메인, JSON/XLS 다운로드**(냉장/냉동 min-max)
→ **우리 "식약처 참고값 추정" 계획에 실제 데이터 기반이 있음.** 둘 다 "전 제품 일괄적용 불가" 명시(참고용).
출처: github.com/shguan10/piweek2018, kfia.or.kr, catalog.data.gov/dataset/fsis-foodkeeper-data

**F3. 수동입력 부담 → 입력수단 다양화가 상용 패턴** (high)
Wonder Fridge = **바코드 + AI사진 + 영수증 OCR 자동등록** 3종(2023엔 수동만 → 마찰 줄이려 추가). 극단=냉장고내 Pi카메라(하드웨어). **영수증 OCR(우리 경로) = 검증된 상용 중간지점.**
출처: play.google.com/…com.meolly.fridge, github.com/shguan10/piweek2018

**F4. 출시되는 낭비감소 기능 = 임박 알림 + 임박재료 레시피 추천 (우리 계획과 동일)** (high)
CozZo 'Cook Expiring Products', Wonder Fridge '소비기한 알림', 냉장고파먹기 '냉장고 재료 레시피'. **3개 독립 앱이 같은 기능쌍으로 수렴.**
출처: cozzo.app, play.google.com/…, apps.apple.com/…냉장고파먹기

**F5. 우리는 재고관리형(마켓형 아님)** (high) / **F6. 수익모델 = 구독/무료OSS/마켓수수료, 단 카테고리 상업적 지속성 취약**(medium — CozZo 종료·Grocy 무료가 경고)

## 4. 우리에게 주는 명확한 시사점
1. ✅ **방향 검증**: 우리 접근(영수증 OCR + 식약처 참고값 + 임박알림 + 레시피매칭)은 **미검증 실험이 아니라 업계 주류.** 안심하고 가도 됨.
2. ✅ **데이터 기반 실재**: 식약처 참고값(2,037) + FoodKeeper(CC0)로 소비기한 추정층의 **실제 데이터가 있음.**
3. 🎯 **진짜 승부처(남들이 문서화 안 한 것)** = **"영수증 OCR 품목 → 올바른 식약처 카테고리 참고값 매칭"**(자유텍스트 품목명 → 카테고리 분류). 이게 load-bearing 엔지니어링이고 우리 NER·품목마스터(§6.3)가 붙는 지점 = **차별화 기회이자 리스크.**
4. ⚠️ **알려진 실패모드 = 수동입력 부담**(유저가 재고를 계속 안 넣음). 완화책=영수증 OCR 자동등록(우리 보유). 단 리텐션 근거는 이번 조사에서 **약함**(§5).
5. 🇰🇷 **차별화**: 한국 식약처 참고값 + 한국 레시피 NER + 한국 1인가구 타겟 = 데이터 확보 가능하고 일관된 제품.

## 5. 한계·주의 (정직하게)
- 대부분 근거 = **벤더/앱스토어 문구**(포지셔닝·기능은 신뢰, **실효성·리텐션은 미검증**).
- **리텐션/이탈 가설(수동입력 부담→이탈)이 가장 약함**: 관련 주장·유통기한 언제지 3건·Wonder Fridge 유저리뷰 주장 **전부 반증**. 앱들이 마찰 줄이려 투자하는 건 명백하나 직접 근거는 부족.
- 참고값 데이터셋 = **카테고리·지역별**(FoodKeeper=미국, 식약처=한국), "일괄적용 불가" 명시.
- CozZo=종료 중(과거 벤치마크로만).

## 6. 미해결 질문 (다음 조사/설계 안건)
1. 개인 재고관리 앱의 실제 리텐션 동인은? (수동입력→이탈 가설이 직접 근거 없음)
2. 카테고리 추정값이 유저에게 얼마나 정확·수용되나? UI가 "이건 추정치지 포장 날짜 아님"을 어떻게 전달?
3. **영수증 OCR 품목 → 식약처 카테고리 참고값 자동 매칭 파이프라인** 구체 설계 (아무 앱도 문서화 안 함 = 핵심 공백).
4. 한국 1인가구 대상 재고관리형의 상업적 지속성? (CozZo 종료·Grocy 무료가 의문)
