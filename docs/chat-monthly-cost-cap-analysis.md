# 챗봇 Gemini 월 예산 상한 — 코드측 상한값 선정 분석

> **작성:** 건우(AI) · **목적:** 챗봇 코드에 넣을 **월 예산 상한(`monthly_budget_won`)의 값을 근거 기반으로 선정**.
> **관련:** `chat-gemini-adoption.md §6`(호출당 비용·Google 청구 상한 실측) · `chat-assistant-ai.md §7`(하드캡) · 이슈 #147(Gemini 키 실서버 적용) · 가드레일 일일 상한(구현됨)
> **상태:** 분석·권고. 최종 값은 팀 확인 후 확정.

## 0. 결론 (요약)

- **권장값: 월 예산 `7,200원` (= Google 청구측 상한 8,000원의 90%), 호출 환산 ≈ 120,000 신규 추천 호출/월.**
- **한 줄 근거:** 현실 최악 사용량(월 ~9,000호출·~570원)의 **약 13배**여서 정상·고성장 운영에선 안 닿고, Google 청구 하드캡(8,000원)보다 **10% 낮아** 그 전에 **무료 template로 우아하게 강등**(서프라이즈 청구 방지 + 카운터 오차 버퍼)한다.
- **성격:** 정상 트래픽을 제한하는 값이 아니라 **버그·남용 폭주만 막는 브레이크**. 기본 flag OFF.

---

## 1. 배경 — 왜 "코드측" 상한이 또 필요한가

Google 콘솔에는 **이미 월 청구 상한 8,000원**이 설정돼 있다(`chat-gemini-adoption.md §3·§6`, 프리페이드 16,000원). 그런데 그건 **billing 하드 스톱**이라, 한도 도달 시 API가 **에러를 뱉는다**. 우리 코드는 API 오류 시 template로 fallback하므로 죽지는 않지만:

- 사용자에겐 **경계에서 불규칙한 실패**로 보이고(운 나쁜 요청만 template),
- **왜 강등됐는지 안내(배너)가 없다.**

**코드측 상한**은 Google 하드 스톱보다 **먼저·의도적으로** template로 내려 **일관된 배너("이번 달 이용량이 많아 간단 모드")**를 제공한다. 즉:

| 층 | 트리거 | 동작 | 성격 |
|----|--------|------|------|
| 코드 월 상한(본 문서) | 7,200원 상당 도달 | template 강등 + 배너 | **1차·우아한 브레이크** |
| Google 청구 상한 | 8,000원 도달 | API 정지(코드가 template fallback) | **최후 하드 스톱** |

두 층이 **defense-in-depth**를 이룬다. 코드 상한을 Google보다 **낮게** 두는 게 핵심.

## 2. 비용 모델 (실측 인용)

`chat-gemini-adoption.md §4`의 실측:

| 항목 | 값 | 출처 |
|------|-----|------|
| 호출당 입력 토큰 | ~174 | 실측(refine-only 프롬프트) |

**과금 대상은 "처음 나오는 레시피 추천 질문"뿐** — 거절·가격·영양·반복질문(30일 캐시)은 **0원**(§5의 3레버: 거절 skip / recommend-only / 캐시).

## 3. 예상 트래픽 시나리오

`chat-gemini-adoption.md §6.2` + 성장·극단 시나리오를 추가 산정(호출당 0.06원):

| # | 시나리오 | 신규 추천 호출/월 | 비용/월 |
|---|----------|------------------:|--------:|
| A | 초기(데모·소수 유저) | 수천 | 수백 원 |
| B | **현실**: DAU 500 × 어시스턴트 20% × 3회/일 × 캐시 50% | ~4,500 | **~285원** |
| C | 현실-최악: B에서 캐시 0% | ~9,000 | **~570원** |
| D | **성장 10×**: DAU 5,000 × 20% × 3회/일 × 캐시 0% | ~90,000 | **~5,400원** |
| E | 폭주(버그 무한재시도·스팸) | 수십만+ | 상한까지 |

- **정상 운영(B)**: 월 300원 안팎.
- **10배 성장 + 캐시 0%(D)**: 그래도 ~5,400원 — 아직 8,000원 미만.
- 상한이 실제로 의미를 갖는 건 **E(폭주)뿐**. → 상한 = "정상 제한"이 아니라 "**폭주 차단**".

## 4. 상한값 선정 — 밴드 도출

상한은 두 경계 사이에 있어야 한다:

- **하한(넘겨야 함)** = 정상·고성장 트래픽 천장. 시나리오 **D = ~90,000호출(~5,400원)**. 여기에 안 닿아야 정상 운영을 방해 안 함.
- **상한(밑이어야 함)** = Google 청구 하드캡 **8,000원(≈133,000호출)**. 이 전에 강등해야 우아함 + 버퍼.

→ **선정 밴드 = 약 5,400원 ~ 8,000원.**

**권장: 7,200원 (밴드 상단부, 청구캡의 90%) ≈ 120,000 호출.**

| 기준 | 값 | 판정 |
|------|-----|------|
| vs 현실 최악(C, 9,000호출) | **약 13배** | ✅ 정상운영 절대 안 닿음 |
| vs 10배 성장(D, 90,000호출) | 약 1.3배 | ✅ 고성장도 여유 |
| vs Google 청구캡(8,000원) | **90% (−800원 버퍼)** | ✅ 하드스톱 전 강등 + 카운터 오차 흡수 |

- **왜 90%(7,200)인가**: 코드 카운터는 Redis INCR로 세는데, 동시요청·재시도로 실제 호출과 미세 오차가 날 수 있다. 청구캡과 **동일(8,000)**이면 경계에서 Google 하드스톱과 겹칠 수 있어, **10% 아래**에서 먼저 끊어 항상 코드가 먼저 우아하게 강등되게 한다.
- **대안(허용)**: 청구캡과 정렬해 **8,000원(100%)**로 두는 것도 방어적으로 합당(단순함·번호 일치). 90%를 1순위 권고.

## 5. 민감도 분석 (값이 견고한가)

| 변수 | 변화 | 영향 | 권장값 견고성 |
|------|------|------|--------------|
| **트래픽 성장** | DAU 500→5,000(10×) | ~5,400원(D) | 7,200원 아래 → **여전히 안 닿음** |
| **캐시 히트율** | 50%→0% | 호출 2배 | C/D에 이미 반영 → OK |
| **단가 인상** | 0.06→0.12원(2×) | 예산제 값이면 **호출캡 자동 반감**(120k→60k), 예산 7,200원 유지 | **원(₩) 기준 config면 자동 적응** |
| **출력 토큰** | 71→200(상한) | 호출당 ~0.06→~0.10원 | 예산제면 자동 흡수 |
| **환율** | ₩1,380/$ 변동 | 단가 변동 | 예산제 config면 흡수 |

→ **상한을 "호출 수"가 아니라 "원(₩) 예산"으로 설정**하면 단가·토큰·환율 변동에 **자동 적응**한다. (호출 카운터 × 실측 단가로 환산.) 이게 값을 오래 견고하게 유지하는 핵심 설계 결정.

## 6. 권장 설정 (구현 시)

```python
# config (기본 OFF — 현 동작 보존, gemini 실서버 활성 시 ON)
monthly_cap_enabled: bool = False
monthly_budget_won: int   = 7200     # Google 청구캡 8,000원의 90% (§4)
gemini_cost_per_call_won: float = 0.06   # 실측(§2). 요율·환율 변동 시 갱신
# 파생 호출 상한 = monthly_budget_won / gemini_cost_per_call_won ≈ 120,000
```

**동작**: 실제 유료 refine 호출 시 Redis `chat:cost:{연월}` +1 → 요청 처리 전 `카운터 × 단가 ≥ monthly_budget_won`이면 template 강등 + 배너. 키 TTL ~35일(월 자동 리셋). 기존 일일 상한의 강등·배너 경로 재사용.

## 7. 기존 안전장치와의 관계 (5중 방어)

1. **구조적 최소화** — refine-only·거절 skip·recommend-only·30일 캐시 → 신규 추천만 과금.
2. **유저별 일일 상한**(구현됨, 200 req/일) — 한 사람 남용 차단.
3. **코드 월 예산 상한**(본 문서, 7,200원) — 전체 폭주 1차 브레이크(우아한 강등).
4. **Google 청구 상한**(8,000원) — 최후 하드 스톱.
5. **프리페이드 16,000원** — 상한 2개월치 버퍼, 자동재충전 서프라이즈 차단.

2·3은 코드, 4·5는 결제 인프라. 축이 달라 서로를 보완한다.

## 8. 가정·검증 필요

- ⚠️ **Flash-Lite 요율**($0.10/$0.40 per 1M)은 시점 변동 → 활성화 전 **현재가 확인**. 변동 시 `gemini_cost_per_call_won`만 갱신(예산 원값은 유지).
- ⚠️ **만개/모델 변경**·Bedrock 이전 시 단가 재산정(`chat-assistant-ai.md §3`: Bedrock엔 Gemini 없음 → Nova/Claude로 모델 변경, 크레딧 충당 시 실지출 0 수렴).
- 실측 토큰(174/71)은 현재 프롬프트·근거 길이 기준 — 프롬프트 개편 시 재측정.

## 9. 재검토 트리거

- **DAU 3,000~5,000 지속** 도달(밴드 하한 근접) → 상한·예산 재산정.
- **캐시 히트율**이 가정(50%)보다 크게 낮음.
- **Gemini 요율·환율** 유의미 변동.
- **백엔드 이전**(Bedrock) — 비용이 크레딧으로 전환되면 상한 로직 목적 재정의.
