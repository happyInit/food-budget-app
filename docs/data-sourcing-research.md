# 데이터 소싱 벤치마크 조사 — 유사 프로젝트·SaaS는 가격 데이터를 어떻게 얻나

> **팀 논의 입력용 조사.** 작성 2026-07-12 · `data-gap-analysis.md`의 후속(§5 딜레마 돌파구 탐색).
> ⚠️ `design.md`(SSOT) 미수정. 채택은 팀 결정.
> 방법: deep-research 하네스(5앵글 fan-out 웹검색 → 22소스 fetch → 96주장 추출 → **적대적 검증 1표** → 종합). 통계: 25검증 → **19 confirmed / 6 refuted** → 7 findings. 검증은 토큰 절약 위해 3표→1표로 축소(신뢰도 라벨 참고).

## 1. 한 줄 결론

**"소매 가격을 합법·대용량·(준)실시간"으로 한 방에 주는 소스는 국내외 어디에도 없다.** 대신 실존 사례들은 **세 가지 합법 패턴의 조합**으로 푼다: ① **공공 소매가 OpenAPI**(합법·소매 ✓, 대용량/실시간 △) ② **크라우드소싱/영수증 패널**(합법 ✓, 커버리지 희소·콜드스타트 ✗) ③ **SKU별 온디맨드 폴링**(폴센트式 — 벌크 크롤이 아니라 유저 URL 기반, 국내에서 쿠팡까지 상용 운영 중). 우리 난제의 가장 현실적 돌파는 **①로 예산 baseline을 합법 확보 + ③로 SKU 비교를 좁게 실현 + ②를 유저 영수증으로 부트스트랩**하는 하이브리드다.

## 3. 검증 통과 발견 (요지 + 출처)

**F1. 한국에 합법·무료 정부 소매가 OpenAPI가 둘 존재한다** (high, 3표 병합)
도매/경락가가 아닌 **소매 체감가** — 우리가 "도매는 페르소나 무관"으로 뺀 자리를 정면으로 메운다. 단 둘 다 ~120품목 **집계** 수준(개별 SKU/점포 단위 아님) → **예산 baseline·물가보정용**으로 유효, SKU 비교엔 부분 대체재.
> ⚠️ **주목**: 통계청 15080757은 우리 `design.md §3.3`에서 *"온라인가격(15080757) → 마켓컬리 조회로 대체"*로 **드롭한 바로 그 소스**다. 합법·일별·무제한 라이선스인데 회색 단일 소스로 갈아탄 셈.
출처: data.go.kr/data/3043385, data.go.kr/data/15080757

**F2. 폴센트는 우리 "롱테일 온디맨드" 설계 그대로 상용 운영 중** (medium, 2표 병합)
대량 카탈로그 크롤이 아니라 **유저가 URL 등록 → SKU별 하루 5-10회 폴링**으로 쿠팡 포함 6개 리테일러 추적. 쿠팡 접근이 공식 쿠팡파트너스 API인지 개별 스크래핑인지는 **미공개**(→§6 미해결). **벌크 쿠팡이 가능함을 증명하진 못하지만, 좁은 온디맨드 SKU 추적은 국내에서 이미 상용**임을 증명. `design.md §3.1`의 "롱테일은 조회 시 온디맨드"와 정확히 부합.
출처: fallcent.com

**F3. 크라우드소싱/영수증이 세계적으로 지배적인 "합법 비크롤링" 모델** (high, 5표 병합)
Open Prices(사진 증빙 + ODbL)가 정본. **합법은 완전 충족하나 콜드스타트/희소성이 치명**(국가당 평균 ~2,300건). 우리는 이미 유저 영수증 OCR(냉장고·캘린더)을 계획 → **국내판 크라우드소싱 가격DB의 씨앗으로 재활용** 가능. 단 초기 커버리지는 정부 API/온디맨드로 보완 필수.
출처: prices.openfoodfacts.org, github.com/openfoodfacts/open-prices

**F4. 크라우드소싱 스케일엔 "유료 인력 보강"이 사실상 필수** (medium, 2표 병합)
Basket조차 순수 크라우드소싱으론 밀도 부족 → 월 1,000~3,000명 유료 모더레이터로 보강. **학생 예산 프로젝트가 순수 크라우드소싱만으로 충분한 밀도를 기대하기 어렵다는 교훈.**
출처: foodnavigator-usa.com

**F5. 사설 API/스크래핑의 법적 현실 = "형사는 잘 안 걸리나 민사 리스크 실재"** (high, 5표 병합)
야놀자 v 여기어때: 형사(대법 2021도1533)는 **기술적 보호조치 없는** 공개 사설 API 크롤을 무죄, 그러나 민사(서울고법)는 **경쟁영업 목적** 무단수집을 부정경쟁행위로 **10억 배상**. 시사점: (a) 마켓컬리가 **Akamai式 봇차단을 걸면** '기술적 보호조치'로 인정돼 형사 유리 논거가 뒤집힘. (b) 우리의 **비상업·교육용**은 민사 '경쟁영업' 요건을 못 채워 리스크를 낮추는 방향(단 판례상 직접 검증 안 됨).
출처: 대법원 판결문 PDF, danawa/etnews 보도

**F6. 대형 플레이어조차 제휴 없이 공개 진열가를 스크래핑한다** (high)
Instacart가 Target 공개가 스크래핑+마크업 자인(2025.12 조사). 업계 관행이지만 **소비자 신뢰/규제 리스크** 동반 → 우리 마켓컬리 회색지대와 동형.
출처: consumerreports.org

## 4. 우리 난제 돌파구 후보 (팀 결정 대기)

조사가 가리키는 현실적 조합 — **어느 하나가 아니라 계층 구조**:

1. **[baseline·합법] 공공 소매가 OpenAPI 재도입** — 통계청 15080757(일별·소매·무제한) + 한국소비자원 참가격. **드롭 결정을 재검토.** 페르소나 지적을 정면으로 해소(소매가). 대용량 SKU는 아니므로 **"물가 baseline / 예산 보정 / 시세 방향성"** 축으로 포지셔닝.
2. **[SKU 비교·현실] 폴센트式 온디맨드 폴링** — 벌크 크롤을 버리고 **유저가 담은 상품만 SKU별 온디맨드 조회**. 우리 `design.md` 롱테일 설계와 일치, 국내 상용 선례 존재. **먼저 쿠팡파트너스 어필리에이트 API가 SKU 가격을 합법 제공하는지 확인**(→§6).
3. **[콜드스타트 부트스트랩] 유저 영수증 크라우드소싱** — 이미 계획한 영수증 OCR을 Open Prices式 실구매가 DB 씨앗으로. 단 F4대로 순수 크라우드소싱만으론 부족 → ①②로 보완.
4. **[리스크 관리] 마켓컬리는 "프리미엄 보조축"으로만** — F5·F6대로 회색지대 + 프리미엄 편향. 비상업·교육 전제 유지, Akamai式 차단 여부 확인(형사 논거 좌우).

> **인프라 서사와의 정합(§gap-analysis §4-A)**: ①은 일별 배치, ②는 유저 트리거 이벤트 → Kafka 이벤트드리븐/온디맨드 파이프라인과 자연 정합. "예측가능 스파이크"는 ③ 크라우드소싱 유입 + ② 온디맨드 버스트로 서사 유지 가능.

## 5. 반증된/신뢰불가 주장 (투명성 — 전제 금지)

- ✗ **"MealMe = 북미 상위 100대 리테일러 실시간 SKU 피드 상용 API"** (0-1) → **대규모 합법 실시간 소매 피드가 기성품으로 존재한다고 단정 금지.**
- ✗ "네이버가 위메프에 메타쇼핑 크롤 C&D 발송" (0-1) — 인용 자제.
- ✗ "가격 같은 단순사실 DB는 제작자권리 보호가 약하다" (0-1) → **사실 데이터 DB보호가 무조건 약하다고 전제하지 말 것.**
- ✗ Mealime "가격 없이도 성공" 2건 (0-1) — 인용 자제.
- 🔻 Trolley.co.uk/MySupermarket(영국) 폐업(가격데이터 aggregator 소유권/라이선스 비용) — 검색엔 잡혔으나 forum/불신뢰 소스라 검증셋 미포함. **"가격 데이터 라이선스 비용이 서비스를 죽인다"는 실패 가설로만 참고.**

## 6. 미해결 질문 (팀 회의 안건 / 다음 research)

1. **폴센트는 쿠팡 가격을 실제로 어떻게 가져오나** — 쿠팡파트너스 어필리에이트 API인가 개별 스크래핑인가? 이 답이 "승인된 준벌크 채널 존재 여부"를 가른다. ← **다음 조사 1순위.**
2. 쿠팡파트너스·네이버 쇼핑파트너 API가 **SKU 단위 '실가격'을 합법 대량 제공**하는가(상품 URL·수수료 메타만인가)?
3. 우리 **비상업·교육용**이 부정경쟁방지법 민사 리스크를 실질적으로 낮추는가(판례 직접 판단 없음)?
4. 마켓컬리가 Akamai式 봇차단/레이트리밋을 운영 중인가(형사 '기술적 보호조치' 인정 수준)?
