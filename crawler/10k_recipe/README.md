# 만개의레시피 크롤러

월 식비 예산 앱(food-budget-app)의 **레시피·재료 수집기**. 만개의레시피(10000recipe.com)에서
추천순 목록을 순회하며 상세 페이지의 재료·조리순서·메타정보를 긁어 **CSV**로 떨군다.

- 코드: [`10k_recipe_crawler.py`](10k_recipe_crawler.py)
- 설계 정본 연동: `docs/design.md` §데이터소스(만개의레시피, 사전 크롤링, 주 1회, P0) · §4(재료 NER 입력)

> ⚠️ **정책 플래그(사전 확인 필요)** — `docs/data-validation.md` §2.2: 만개의레시피 robots.txt는
> `Content-Signal: ai-train=no`(EU DSM 2019/790 제4조 권리유보)와 함께 ClaudeBot·GPTBot·CCBot 등
> AI 크롤러를 명시적으로 `Disallow: /` 처리 — 이 프로젝트의 핵심 용도(CRF NER 학습 입력)를 정면으로
> 겨냥한 TDM 옵트아웃으로 **🔴 블로커 판정**되어 있다. 이 크롤러는 일반 브라우저 UA를 쓰고 있어
> 라이브 요청 자체는 `200 OK`가 떨어지지만(명명된 봇만 차단하는 방식이라 우회됨), robots.txt의
> 권리유보 취지와는 배치된다. **소스 채택·사용 범위는 design.md(SSOT)에 아직 이 판정이 반영되지
> 않은 상태이므로 팀 결정 대기.**

## 1. 어떻게 크롤링하나

```
① 목록  : GET /recipe/list.html?order=reco&page={n}   (추천순 목록, 서버렌더 HTML)
            → 상세 URL 목록 추출 (선택자 폴백 4단)
② 상세  : GET /recipe/{id}                             (서버렌더 HTML)
            → 제목/요약/작성자/인분/시간/난이도/재료/조리순서/태그 파싱
출력    : CSV 4종 + 재개용 상태 파일 (아래 §3)
```

- **스트리밍 + 재개 가능**: 페이지 단위로 처리하며 매 페이지 완료 시 `크롤링_상태.json`에
  `last_completed_page`를 기록. 재실행 시 그 다음 페이지부터 이어서 진행.
- **중복 방지**: 기존 CSV에서 이미 수집/제외된 URL을 시작 시 로드해 재요청하지 않음.
- **동시성**: 페이지 내 상세 요청은 `ThreadPoolExecutor(max_workers=3)`. 실제 HTTP 요청은
  전역 락(`request_lock`)으로 직렬화하고 요청마다 0.6~1.2초 랜덤 지연을 둬 동접이 아니라
  "3개 워커가 번갈아 순서대로" 요청하는 구조에 가까움.
- **재시도**: `urllib3.Retry`로 429/5xx는 최대 3회 백오프 재시도.
- **검증 실패 시 제외**: 제목/작성자/재료 섹션/재료개수/조리단계 중 하나라도 없으면
  `제외_레시피.csv`에 사유(`TITLE_MISSING` 등)와 함께 기록하고 본 데이터에서 제외.

## 2. 어떤 데이터를 뽑나 — 출력 파일 & 필드 스키마

| 파일 | 내용 |
|---|---|
| `공식_레시피.csv` | 작성자가 `OFFICIAL_AUTHORS`(현재 `"만개의레시피"` 계정 1개)에 속하는 레시피 |
| `일반_검증완료_레시피.csv` | 그 외 검증 통과 레시피 |
| `레시피_재료.csv` | 레시피별 재료 1행씩 (정규화 전 원문 보존) |
| `제외_레시피.csv` | 검증 실패 URL + 사유 |
| `크롤링_상태.json` | 마지막 완료 페이지 + 카운트 (재개용) |

### 레시피 CSV (`공식_레시피.csv` / `일반_검증완료_레시피.csv`)

| 필드 | 소스 위치(HTML) | 비고 |
|---|---|---|
| `레시피ID` | URL `/recipe/{id}` | PK |
| `레시피URL` | 목록 페이지 링크 정규화 | 중복 체크 키 |
| `제목` | `.view2_summary h3` | |
| `요약` | `.view2_summary_in` | |
| `인원` / `시간` / `난이도` | `.view2_summary_info span` (`info1`/`info2`/`info3`) | 클래스 없으면 순서 폴백 |
| `재료` | 재료 리스트 요약(이름+수량 join) | 사람이 읽는 요약용, 구조화 데이터는 재료 CSV |
| `재료개수` / `조리단계수` | | |
| `조리순서` | `.view_step_cont` 계열 (번호 매겨 join) | |
| `태그` | `.view_tag a` | |
| `작성자` | `.profile_cont` 계열 | `by ` 접두어 제거 |
| `작성자구분` | `OFFICIAL` \| `GENERAL` | `작성자 in OFFICIAL_AUTHORS` |
| **`품질점수`** | 계산값(0~100) | ★ 아래 §2.1 |
| `데이터검증상태` | 항상 `VALID`(검증 실패는 이 파일에 안 들어옴) | |
| `수집일시` | 수집 시각 | |

#### 2.1 품질점수 계산 (`calculate_quality_score`)

제목(10)·요약(5)·재료존재(20)·재료≥3(10)·재료≥5(5)·조리순서존재(20)·단계≥3(10)·단계≥5(5)·
인원(3)·시간(3)·난이도(2)·태그(2)·공식작성자(5) 가산 + 재료 중 수량이 기입된 비율이
80%↑면 +5, 50%↑면 +3. 상한 100.

### 재료 CSV (`레시피_재료.csv`)

| 필드 | 비고 |
|---|---|
| `레시피ID` / `레시피URL` | 조인 키 |
| `재료순번` | 레시피 내 순서 |
| `재료그룹` | 리스트 상단 `b`/`strong`/`dt`/`h4`/`h5` 텍스트(예: "재료", "양념") — 못 찾으면 `"재료"` |
| `재료명` | `<a>` 태그 우선, 없으면 원문에서 정규식(`split_ingredient_text`)으로 수량부 분리 |
| `수량` | `<span>` 텍스트 우선("구매" 문구 제외), 없으면 정규식 폴백 |
| `재료원문` | 정제된 원문 그대로("구매" 버튼 텍스트 제거) — **CRF NER 입력은 이 컬럼 기준** |
| `작성자구분` / `수집일시` | 레시피 CSV와 동일 |

> 재료명/수량 분리는 CSS 선택자(`<a>`, `<span>`) 우선이고, 실패 시에만 정규식 폴백을 탄다.
> 정규식은 `약간·적당량·조금` 같은 비수치 표현까지 커버하지만 자유텍스트 특성상 완전하진 않음
> — 표준 품목코드 매핑은 `재료원문`을 CRF NER에 넣어 별도 처리(§6.3, 이 크롤러 스코프 밖).

### 제외 CSV (`제외_레시피.csv`)

`레시피URL` / `제외사유`(`TITLE_MISSING` · `AUTHOR_MISSING` · `INGREDIENT_SECTION_MISSING` ·
`INGREDIENTS_MISSING` · `STEPS_MISSING` · `HTTP_ERROR_{code}` · `REQUEST_ERROR` · `PARSING_ERROR`) /
`확인일시`.

## 3. 사용법

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt

python3 10k_recipe_crawler.py
```

- 실행 위치(cwd)에 CSV 4종 + `크롤링_상태.json`을 생성/추가한다. `--out` 같은 CLI 옵션은 없음 —
  대상 수량·페이지 상한·동시성 등은 파일 상단 상수를 직접 고쳐서 조정:

| 상수 | 기본값 | 의미 |
|---|---|---|
| `TARGET_TOTAL_COUNT` | 10000 | 목표 전체 레시피 수(공식+일반). 도달 시 자동 종료 |
| `MAX_LIST_PAGES` | 1000 | 목록 페이지 순회 상한 |
| `MAX_WORKERS` | 3 | 상세 페이지 동시 처리 스레드 수 |
| `REQUEST_DELAY_MIN/MAX` | 0.6 / 1.2초 | 요청 간 랜덤 지연 범위 |
| `MIN_INGREDIENTS` / `MIN_STEPS` | 1 / 1 | 검증 최소 기준 |

- `Ctrl+C`로 중단해도 그 시점까지 CSV·상태 파일은 그대로 남고, 재실행하면 `크롤링_상태.json`
  기준으로 다음 페이지부터 이어서 진행한다.
- 목록이 3페이지 연속 비면 자동 종료.

## 4. 크롤 정책 (현재 코드 기준 — 확정 아님, 위 정책 플래그 참조)

- 요청 간 최소 0.6~1.2초 랜덤 지연 + 429/5xx 백오프 재시도(최대 3회) — 서버 부담 완화 시도는 있음.
- **User-Agent가 실제 Chrome 브라우저 문자열**(`Mozilla/5.0 ... Chrome/124.0.0.0 ...`)이라
  오아시스 크롤러(연락처 명시된 커스텀 UA)와 달리 요청 주체가 식별되지 않음. robots.txt가
  명명된 AI봇만 차단하는 구조라 결과적으로 그 차단을 우회하는 형태가 된다 — §정책 플래그 참조.
- 개인정보(리뷰·댓글·프로필 사진) 수집 없음. 레시피 텍스트·재료·메타만.

## 5. 알려진 한계 · 다음 작업

1. **공식/일반 판별이 매우 제한적**: `OFFICIAL_AUTHORS`에 `"만개의레시피"` 계정 하나만 등록됨 —
   실제 공식 큐레이션 계정이 더 있다면 전부 `GENERAL`로 분류됨.
2. **선택자 다중 폴백 의존**: 목록 페이지는 선택자 4종을 순서대로 시도(`common_sp_link` 등),
   상세 페이지도 유사 — 사이트 개편 시 조용히 빈 결과를 낼 수 있어 주기적 실측 확인 필요
   (오아시스와 동일 트레이드오프).
3. **`schema.org/Recipe` JSON-LD 미활용**: 상세 페이지에 `<script type="application/ld+json">`으로
   제목·이미지·작성자·게시일 등이 구조화되어 있음(실측 확인). 현재는 HTML 선택자만 쓰는데, 이후
   선택자 깨짐에 대한 폴백 소스로 검토 가능.
4. **재료 수량 파싱은 자유텍스트 정규식 기반**: `약 200g`처럼 변형이 많은 표기는 놓칠 수 있음 —
   표준화는 크롤러 책임이 아니라 후단 CRF NER 몫으로 의도적으로 분리됨.
5. **샘플 출력 미포함**: 오아시스(`sample_output.jsonl`)와 달리 이 저장소엔 아직 실행 샘플이 없음.
   이 작업 환경에 `beautifulsoup4`가 설치되어 있지 않아(pip/venv 불가) 직접 실행해 생성하지 못했음
   — 로컬에서 소량(`TARGET_TOTAL_COUNT`를 임시로 낮춰서) 실행 후 `sample_output/`에 커밋 권장.
