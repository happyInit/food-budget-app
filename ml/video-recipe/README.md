# 유튜브 영상 → 레시피 추출 (스캐폴드)

`video-recipe-ai.md` 설계의 파이프라인 구현. **온디맨드**(유저가 URL 제출) — 영상을 Gemini로
분석해 구조화 레시피(재료·타임스탬프 스텝)를 추출한다. 팀 승인된 유료 Gemini 사용, **비용
최소화** 설계. 키 없으면 무동작(안내 폴백) — prep-ahead.

```
URL 정규화 → 교차유저 캐시(히트=비용0) → 1차 추출 → 규칙검증(H1~H5)
  → (하드실패 1회) 재분석 → 소프트플래그(S1~S3) → (선택)정제 → 캐시저장 → NER 정규화
```

## 모델 선정 — 비용·효율 (재검토)

**영상 토큰이 비용의 90%+** 이므로 1차 추출은 **가장 싼 모델**. 전부 env로 교체 가능:

| 역할 | 기본 모델(env) | 근거 |
|------|----------------|------|
| **1차 추출**(영상→JSON) | `gemini-flash-lite-latest` (`VIDEO_EXTRACT_MODEL`) | 최저가 · 영상 1회 통과. 코드베이스(chat·ocr) 일관 |
| **재분석**(하드실패 1회만) | `gemini-flash-latest` (`VIDEO_RETRY_MODEL`) | 실패 건만 → 기대 비용 낮음 |
| **정제**(텍스트만, **기본 OFF**) | `gemini-flash-latest` (`VIDEO_REFINE_MODEL`, `VIDEO_REFINE_ENABLED`) | 1차 품질 부족 시에만 켬 — 기본은 비용 절감 |

**설계문서 대비 최적화**: 문서는 정제를 최고 flash로 상시 수행했으나, **정제를 선택(OFF 기본)**
으로 바꿔 건당 비용을 더 낮춤(정제 스킵 시 ~$0.008 절감). 추출 실패율이 낮으면 1차만으로 충분.
Pro는 배제(듣고 정리에 우위 없음, 비용만↑). **교차유저 캐시(TTL 30일)로 인기 영상은 비용 0.**

예상 단가: 캐시·정제OFF 반영 시 건당 **~$0.05 이하**. 무료 티어(유튜브 하루 8시간)로 PoC는 $0.

## 검증 (규칙 기반, 비용 0)
- **하드(H1~H5)** → 재분석 트리거: H1 파싱/스키마·H2 재료0/스텝<2·H3 요리명null·H4 타임스탬프
  단조위반/길이초과·H5 스텝중복>50%.
- **소프트(S1~S3)** → 플래그(재분석 X): S2 **NER 사전 매칭 실패율>40%**(자체 재료사전이 검증기)·
  S3 설명란 교차검증.
- 재분석도 실패 → **안내 폴백**(수동 입력 유도), **무한 재시도 금지**.

## 활성 조건 (코드 밖)
- **`VIDEO_GEMINI_API_KEY`**(유료 Gemini, 팀 승인) — 없으면 무동작.
- NER 정규화(`ner_match_fn`)·Redis 캐시·프론트(`YoutubeExtract.tsx`)·게이트웨이 라우트 배선.
