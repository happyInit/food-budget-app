# 개인화 랭킹 — 발표용 검증 데모

ML 개인화 랭킹(P1)이 규칙 랭킹(P0)보다 나은지를 **한 명령으로 재현**하는 발표용 데모.
실사용자 데이터가 없어도(축적 전) 개인화가 **동작하는 모습**을 보여준다.

```bash
python demo/run_demo.py
#   → demo/out/results.json  (수치)
#   → demo/out/report.html   (발표용 리포트 — 브라우저로 열기)
```
의존: `numpy`, `scikit-learn`(폴백 학습기). `lightgbm` 있으면 정식 LambdaMART, 없으면 sklearn 폴백.

## 무엇을 보여주나

**Layer 1 · 정량** — 페르소나 합성 클릭스트림으로 학습 → 검증셋에서 **NDCG@k·MAP·MRR을 규칙
baseline 대비 lift**로 측정. (예시 실행: NDCG@5 규칙 0.61 → ML 0.92, **+51%**.)

**Layer 2 · 해석** — 페르소나별 **규칙 순위 → ML 재랭킹** before/after를 **실 레시피명**으로.
규칙은 재고·임박·저비용만 보므로 취향과 무관하게 평평하지만, ML은 유저 행동(재료 선호·과거
참여)을 학습해 취향 레시피를 상위로 올린다:

| 페르소나 | 규칙 1순위 | ML 1순위 |
|----------|-----------|----------|
| 매운 돼지고기 애호가 | 소불고기 | **고추장 삼겹살 두루치기** |
| 저예산 지향 | 새우볶음밥 | **계란말이**(저렴) |
| 닭가슴살 다이어터 | — | **닭가슴살 스테이크** |

## ⚠️ 정직한 범위 (발표 시 명시 권장)
- **mock 기반 오프라인 검증**이다 — 실사용자 데이터가 아님. 실운영 A/B(담기율)는 **데이터
  축적 후** 측정한다.
- 수치는 시연용 합성 신호에서 나온 것으로, 개인화 파이프라인이 **작동함**을 보이는 것이지
  실서비스 개선폭의 예측이 아니다.
- 데이터가 쌓이면 동일 파이프라인(`extract.py`→`train.py`→`evaluate.py`)이 실 데이터로 그대로 돈다.

## 구성
- `personas.py` — 합성 레시피 카탈로그 + 페르소나(취향→라벨) + 학습행/후보셋 생성
- `run_demo.py` — 학습→평가(Layer1)→before/after(Layer2)→results.json·report.html
- `report.py` — results → 발표용 HTML(라이트/다크 대응, 외부 의존 0)
